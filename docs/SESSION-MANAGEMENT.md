# UX-02 会话管理：日常入口、子会话收纳与精确恢复

日期：2026-09-24；核对基线 `c67fe38`。**状态：设计与实施计划，尚未实现统一会话管理。**
本次只检查代码、已有参考、CLI 帮助及官方文档；没有启动模型、扫描私人会话正文、
归档/删除历史、修改宿主配置或迁移存储。全部执行顺序、状态和下一单元统一见
[综合实施计划](IMPLEMENTATION-PLAN.md)，本页只定义 UX-02 的边界和验收。

## 1．目标体验与现状

用户从项目目录打开日常 agent 时，应容易找到自己与主调度方的对话；编排生成的
作者、验证者、原生派生任务按 run 收纳，需要时能展开、查看证据或准确恢复。
“完成历史不挤占日常列表”和“运行中的协作异常不能隐藏”同时成立。

期望的 kumi 视图如下；这是信息结构草图，不是已提供的命令或界面：

```text
项目
  日常/主调度会话                   仅展示明确登记的入口
  本次协作：接口改造                 2 个运行中，1 项待处理
    接口实现 · omp · a13f           等待验证反馈
    兼容性验收 · Codex · c482       运行中
  历史协作                         折叠，可按任务/宿主/日期搜索
```

| 当前已有基础 | 尚未解决的问题 |
|---|---|
| `pages.py` 与 transports 已统一同 space 新 tab、任务＋宿主标题 | tab 标题不等于原生历史标题，关闭 tab 也不等于归档历史 |
| `runs.py`、`jobs.py` 保存 run/job/round、launch、原生 session/turn 与恢复回执 | 没有统一的项目会话目录、可恢复存储定位和原生历史可见性策略 |
| E2E runner 对 omp 使用 `--session-dir`，Hermes 有私有 home 配方 | 属于特定启动路径；不能据此宣称运行 skills 的所有子会话都已隔离 |
| completion、控制租约及原生用量来源登记 | 收起历史尚未与未决消息、后台任务、归档移动后的证据地址接通 |

不通过全局删除旧会话、关闭日志、默认 ephemeral、修改宿主数据库或打本体补丁来
整理列表。Git worktree 按代码隔离需要使用，不为了隐藏会话伪造 cwd 或改变项目指令范围。

## 2．采用两层管理，分别验收

### kumi 的项目会话目录

统一聚合已登记的主调度、作者、验证者及原生派生记录。默认折叠 worker 明细，展示
进行中的 run 和需要处理的事项；失败、待审批、未读超期、未知健康、未完成交接始终
有显眼计数和入口。完成历史按 run 收纳，用户可固定某个 worker 方便日常查看。

先实现 CLI/结构化摘要与恢复入口，复用现有页面能力，不先做完整 GUI。目录是已知
run、job 和启动回执的派生视图，可重建；任务、消息和计量仍各用现有权威记录。
首次登记日常主会话时要求明确身份，仅标为外部/用户拥有，不因同 cwd 就接管它。

### 宿主原生历史列表

逐宿主选择经过验收的策略，记录实际效果：

1. **创建时分开保存历史：** 优先使用只影响 session 存储的受支持选项。业务 cwd、
   模型、认证、审批、skills 和插件保持原契约；新 worker 历史不进入日常默认选择器。
2. **完成后原生归档：** 没有合适的独立 session 存储时，验证原生归档/恢复。运行中的
   worker 可能仍出现在列表里，归档后是否默认隐藏必须实际检查。
3. **只在 kumi 中分组：** 两者都不能安全做到时，保留清楚的标题与 kumi 目录，明确
   标记“原生历史仍可见”。这只是降级体验，不能宣布解决了用户直接打开宿主的拥挤问题。

各 adapter 报告独立能力：存储隔离、原生重命名、默认列表隐藏、归档、恢复、已知派生
范围和证据读取。支持 rename 不推导支持 hide；支持 CLI/API 不推导实际 TUI 已兼容。
会话目录分组与任何特定宿主无关；角色与权限不按支持程度分等级。

## 3．身份、存储与命名

### 目录记录

拟新增启动/会话 sidecar 与可重建索引，不直接给严格 v1 job schema 塞未识别字段：

| 类别 | 拟记录内容 |
|---|---|
| 项目 | 本地 project_id、已确认项目根与 worktree 映射；名称/路径是显示或定位信息 |
| 任务关系 | run/job/round 引用、instance、角色、任务短名、明确的调度/委托关系 |
| 原生身份 | host、配置模式、版本、store/profile 定位、精确 session ID、原生派生/压缩/接班关系及证据 |
| 启动与恢复 | operation_id、argv、非敏感配置引用、cwd、读写范围、传输资源、会话是否确已绑定 |
| 可见性 | kumi 分组/置顶、native 可见/归档/未知、各 adapter 能力与实测依据 |
| 保留与证据 | 原始来源、可读取位置/位置修订、受引用记录、归档回执和保留原因 |

原生定位至少包含 host＋store/profile＋session ID；同一 ID 的复制库或导出不能自动
算成新会话/新计费事件。一个原生会话可以承载同 job 的多轮，关系不能假定一对一。
原生父子、上下文压缩延续和 kumi 委托关系分别记录，不能仅凭 parent ID 归类。
跨项目/跨 run 共用原生会话须有明确记录；第一版不默认复用这种会话。

新启动先登记意图和历史策略，拿到原生身份后再绑定。崩溃或超时保留未绑定/unknown，
不能按最近文件、同名或 cwd 猜测成功然后重复启动。展示索引损坏不改变任务事实。
项目移动、重新 clone、worktree 删除不自动合并身份；显式重关联并校验旧记录。

### 存储位置

沿用当前 `runs.state_root()` 和 run 生命周期。现有默认根保留
`$XDG_STATE_HOME/agent-orchestrator`（未设置时按当前实现回退）；本项不顺带改旧路径。
支持分离的新子会话存储放已登记 run 的受管理目录，首选持久 state，不放临时目录供
长期恢复；暂用原生共享存储的会话只登记精确位置，不宣称已经隔离。
项目源码中不存原生聊天、认证副本或完整历史。若需要项目本地入口，只放明确忽略的
定位信息；不能假定用户项目已有 `.orch` ignore，也不自动改其 AGENTS.md。

分清历史、配置、凭据和缓存：独立 session 目录最优；整 home/profile 隔离是能力更宽
的备选，须证明凭据获取、配置继承、模型、插件与审批行为一致。不要复制整个个人 home，
不要用全局环境变量改变用户之后启动的会话；仅作用于本次子进程/独立服务。
OAuth 刷新存储、MCP、共享 daemon、后台进程与插件路径须逐项验证，不能仅凭目录不同
就声称隔离。收据不记录密钥或完整环境；保留私有访问权限。
run 收尾不自动移除其历史存储；会话、验收、计量和未决责任仍引用它时保留。后续
删除 run 或卸载可选适配器，须先处理这些引用，不能把运行目录误当可随时清空的缓存。

### 命名与复用

任务页继续使用已实现的“任务目的 · agent 类型”；原生会话标题如支持，采用相同任务
名并追加稳定短号，例如“接口实现 · omp · a13f”。角色、run 和轮次在目录中查询，
避免把整个协议写进标题。人工改名后不反复覆盖；title 变化不改变身份。

相关返工优先在原 job 的已核对会话中按现有协议续轮，不每条消息新开一个历史；独立
任务建立新会话。不要为了减少列表条目把所有任务塞进一个永久 worker。接班使用
CQ-03 显式关联与精简交接，旧实例和证据继续可追查。

## 5．归档、恢复、保留和既有历史

执行状态、可见性和保留状态分别保存。kumi 中折叠 ≠ 宿主归档 ≠ agent 停止 ≠
任务验收通过。接收方归档也不解除 M1 的未读/业务责任，不修改旧结果或验收快照。

对明确由 kumi 管理的新 worker，拟采用“验收/收尾成立后可自动整理”的版本化策略；
完成后的首选是可逆归档，不设置自动删除期限。实际 adapter 通过 sandbox 后才能启用。
主调度入口、用户接管/置顶会话、用户原有会话及归属不明历史不自动原生归档。

一次原生归档需满足：

1. 精确会话及所有受影响后代在操作范围内，绑定任务均已收尾；成功/失败/取消分别有
   相应证据。无活跃写入者、未决审批、uncertain 输入和未知停止状态。
2. 消息、交接和业务责任已处置或由明确新负责人确认接管；仍有异常时保持显眼入口。
   失败历史可在处置后收纳，不能为变绿而写成功。
3. 计量与验收所引用的证据仍可访问。原生归档可能改变日志位置：优先留已有支持的
   只读导出/快照或经过校验的位置映射，保留来源 ID、摘要和旧 locator 的历史，不改
   既有不可变 manifest，也不因路径变更重复导入费用。
4. 持久记录意图、范围与版本，锁外调用官方接口，然后逐项读回。部分成功/回执丢失
   保留可对账状态，不把一个成功码等同整组已归档；失败不阻塞其他独立任务。

归档执行与恢复/发送受同一控制所有权约束，并在动作前重验。外部用户或共享 daemon
仍可能造成竞态；无法可靠限定作用域或证明未运行的 adapter 不启用自动归档。
不通过归档强行停止任务，不用 SQL、文件移动或 kill 替代宿主受支持操作。

“查看历史”首先只读，不为了显示正文就启动一个模型回合；“恢复工作”才检查原生
store/profile、会话、cwd、配置与权限，并取得当前输入权。需要 unarchive 的路径先
记录并核对恢复，使用精确 ID；禁止 `--last`、模糊前缀和自动恢复所有后代。旧 job 已
关闭时，只能查看或通过现有协议建立有依据的新工作，不能伪造旧轮仍在运行。
恢复默认不抢焦点；真正继续交互时沿用同 space 新 tab，并复用仍有效的自有页面。

关闭 tab 走现有资源清理门槛，作为独立动作记录。历史归档成功不证明 pane 可关闭，
pane 已消失也不证明会话历史可清理。

既有历史先提供基于已知 run/任务回执的只读盘点与 dry-run，列出“可绑定、需核实、
用户/未知”三类。不扫全 HOME 聊天正文，不按标题前缀或同 cwd 批量认领。旧历史原生
归档/迁移另行选择范围；迁移前备份、逐项读回并记录撤销方式。删除暂不进入首版，
后续若做 GC，必须有引用检查、保留策略和明确范围，不能借清理列表执行永久删除。

## 6．小批次与验收

| 子项 | 范围 | 通过条件 |
|---|---|---|
| UX-02a | 已知 run 的只读项目目录、会话关系与能力记录；启动/历史归档 dry-run | 不加载全部正文；精确区分宿主、store、角色、轮次与原生派生；缺身份/坏索引显式可见，无宿主写入 |
| UX-02b | 新 worker 启动时声明历史策略、统一命名、最小隔离适配 | 五配置分别记录通过/失败/未测；实际日常入口与精确 resume 验证；配置/认证/审批不漂移；错误不静默退回默认历史 |
| UX-02c | 受控归档、只读历史与恢复；接通收尾、消息和计量 | 活跃任务拒绝归档、派生范围检查、部分失败/重启对账、证据移动不丢失、不重复计量、不误恢复旧轮 |
| UX-02d | 旧历史盘点和显式收纳试点 | 用户会话 sentinel 不变；不按名称猜归属；预览、可逆操作和逐项结果齐全；无自动删除 |

与综合阶段的映射：阶段 0 补能力清单，阶段 1 消息记录预留会话定位引用但不重构
M0 地址；阶段 2 做 UX-02a；阶段 4 的真实宿主启动前按配置完成 UX-02b；阶段 5
接入 UX-02c，依赖已完成的消息责任检查。UX-02d 在阶段 5 后独立小批提供旧历史
盘点/预览，实际操作另按明确范围执行；纯文件/模拟测试不受原生隐藏能力限制。
这些是依赖映射，实际顺序只在[综合队列](IMPLEMENTATION-PLAN.md#下一阶段执行队列)维护。

有宿主暂不支持历史隐藏时，可选择明确显示降级状态的有界实验；不能把该配置标为
UX-02 完成或用一个新 kumi 列表替代原生列表验收。M1 消息功能与 UX-02 分别记通过情况。

每个候选配置至少检查：同 cwd 的日常会话与 worker 并存、原生选择器可见性、准确
恢复、两 run 同名任务、相关返工不重复开会话、压缩/接班与原生派生、断电/重启、
待审批/未读超期、背景任务、归档与恢复竞态、源路径变化、删除项目 worktree 后的
历史定位，以及没有已安装 kumi 时日常宿主仍正常启动。全程保留一个非 kumi 用户
会话 sentinel；先合成夹具，后自有 sandbox，有界模型实验另记预算。

最终体验指标是找回主会话所需操作、默认列表中已完成 worker 的数量、历史查找与
恢复成功率、异常可见性和误操作数量。列表变短本身不证明 token 节省；会话目录只
返回必要摘要，正文按需读，成本继续进入 CQ-01/CQ-06 的真实计量。
