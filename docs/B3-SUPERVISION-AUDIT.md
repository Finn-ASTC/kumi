# B3：监督时效审计与主线收口

日期：2026-09-24。主线实现基线 `16988f1`。本批补齐时效复核工具，
**没有实现自动审批，也没有通过 B 的 30 秒原生审批响应目标**。

## 为什么先做这项

[B2](B2-SUPERVISION.md) 已记录发现审批至动作约 100.67 秒，但项目缺少统一的
历史时效统计入口。`handled` 表示复核记账，不能代替实际输入或界面解决。
只统计最后一条告警、只统计成功样本或扣掉声明的人类等待，都可能误报改善。

新增运行 helper `skills/agent-orchestrator/scripts/supervision_audit.py`，按 run
只读审计 attention 和 review 历史。四类宿主使用同一接口和判定规则，不依赖某类
原生 session 格式。接口与退出码见[运行参考](../skills/agent-orchestrator/references/supervision.md#audit-retained-response-timing)。

- 分开统计发现至首次复核记账、至动作证据记账、至最近一次有证据的解决声明。
- 汇总计入全部可读记录，分页不改变统计；p50/p95 使用 nearest-rank，并列样本数。
- 缺少端点保持未知；handled 没有解决证据单列。重新 open 后不继承旧解决声明。
- waiting_user 按声明区间计时，不伪装成人类实际耗时，也不扣除它来制造快速响应。
- 替换 watch、同文案重新出现及不同轮次保持独立，不自动拼成“同一次已批准”。
- 记录损坏、证据改写/缺失、时钟倒退、已检测的并发变化会使报告 incomplete。
- 空样本不能通过；即使复核记账在目标内，仍返回 `approval_response_sla_verified=false`。

本工具不读取现场终端、不消费队列、不写 review，也不运行批准/拒绝。
扫描成本随历史增长，适合阶段末/诊断，不应塞进每个工作检查点。
现有 review 链没有独立的最新 revision 水位；连续尾部被删除时，仅凭剩余文件无法发现。
若丢的是重开记录，旧解决声明可能重新成为最近保留状态。报告明确
`history_completeness_verified=false`；本批不扩展持久化协议来冒称能证明历史完整。

## 旧原生实验只读复核

本次重读 B2 保留的真实实验 run，两份 watch 的 11 条 attention，核对原始文件在审计前后
SHA-256 完全不变。报告写入新的私有 sandbox 目录，原路径和原始正文不进入公开仓库。

| 结果 | 数值/含义 |
|---|---|
| 首次复核记账超过 30 秒 | 11 / 11 条 attention |
| 发现至首次复核记账 p50 / p95 | 98.72 / 141.26 秒 |
| handled 但没有解决证据 | 10 条 |
| 含有效引用的解决声明 | 1 条 |
| 旧版未固定 hash 的事件捕获 | 11 条，显式 legacy_unpinned |
| 已引用动作/解决证据的字节校验 | 通过 |

这 **不是 11 次独立审批**。历史中包含连续界面变化产生的多条事件；既有人工复核
给出约 100.67 秒的发现至实际动作，仍保留其原口径。本工具不解析任意 action 文件里的
自定义字段，不能用“动作证据记账时间”取代实际动作时间。
唯一解决声明相对其关联的较晚事件约 41.09 秒，也不是从最初审批出现开始计时，
不能拿它替换 B2 的全段响应结果。历史证据说明慢响应和记账缺口仍存在，不证明本批提速。

## 验证与接入边界

新增 26 项专项回归覆盖端点区分、等待区间、重开、过期/缺失、关联不转移、分页、坏时钟、
证据变化、文件缺口、并发和五配置同一口径。另把六个 skills 复制到最小目录，通过
独立 CLI 进程执行，验证不依赖仓库 tests、根目录文档或个人 vault。

这是运行包新增 helper；更新接入时仍按完整六个 skills 同步。
`tests/test_supervision_audit.py` 和本报告不需安装。日常 skill 安装本批未自动同步。
没有新原生模型调用；旧实验审计不替代新版本原生控制矩阵、长时监督或真实连续计量。
完整回归 642 项通过（含 15 项真实 tmux，无失败/跳过），分发检查零发现；结果记在[状态页](STATUS.md)，后续具体顺序见[主线收口队列](IMPLEMENTATION-PLAN.md#2026-09-24-主线收口与实验分支分开推进)。
