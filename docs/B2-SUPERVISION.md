## 回归与独立应用验证

新增 18 项回归，覆盖 stdin 的严格解析/大小限制/身份/不覆盖、特殊字符嵌套路径、
60 秒续接边界、旧 blocked/盲读恢复，以及日志半行/续读/超时/替换/截断/非普通文件。
新增功能先在旧实现上观察到失败，再实现并验证。全套 **492 项通过**，含 13 项真实
tmux，零跳过/失败。受限沙箱首次执行不能创建 tmux socket；允许本地 socket 后完整重跑通过。
这些回归不调用模型。

参考资料采用独立上下文应用验证。基线 agent 已能解释既有规则，但指出缺少业务
检查点适配工具，发布还需要候选文件；不把它描述为违反原规则。
更新后另一个 agent 实际运行了两个场景：

- 在含空格、Unicode 的嵌套轮次目录，执行生成的 JSON argv，通过 stdin 发布。
  再次发布退出码 3，原始字节不变；没有候选文件或缩短后的错误目录。
- 只启动一个确定性生产者。检查点约 1.029 秒返回且原进程仍活着；中途一次超时
  保留进程，随后以同一游标/身份在约 3.020 秒读到结束标记，原进程退出码 0。

这是 API 应用验证，不是五组提示词对照或 token 成本实验。

## 短原生验证

独立 sandbox 项目、独立 herdr session，页面命名“验证检查点等待与审批”。
Codex CLI 0.155.0，沿用既有 deepseek-flash high 配置；没有调整模型、审批策略
或安装个人 skills。页面创建使用 no-focus；桌面 viewer 交互仍未验收。

夹具只启动一次 producer：先记录 START，4 秒后输出 CHECKPOINT_READY，
等待一次原生审批允许 probe 写入确切实验回执和 gate，随后输出 STREAM_FINISHED。
输入为整数 1 至 6，独立 oracle 验证总和 21、数量 6、三条日志事件和同一生产者。
probe 的外部回执在声明的实验范围内，但位于子宿主可写目录之外；首次沙箱拒绝，
控制器检查完整原生命令后选择“仅本次允许”，不添加永久规则。

| 观测 | 结果 |
|---|---:|
| 第一次 helper 等待耗时 | 0.601 秒；检查点返回时业务仍运行 |
| 业务检查点 → 观察器发现原生审批 | 22.57 秒 |
| 发现审批 → 控制器动作 | **100.67 秒，未达 30 秒目标** |
| 动作 → 确认结果 | 0.123 秒 |
| 确认 → 对应 attention 处理记账 | 0.006 秒 |
| 单次业务进程跨度 | 129.32 秒 |
| 后一次替换观察器完成 monitor 绑定距旧到期 | 提前 67.42 秒 |

业务只启动一次，保留原生 managed handle；最后取回退出码 0。准确轮次结果一次
发布，未修报告、未重跑业务。固定快照的独立 oracle 通过，seed 源码不变，cwd
仅新增声明的三份生成文件；外部回执与 gate 一致。原生日志未出现另建候选文件
或委派调用。此核对限于声明路径、该会话工具调用及原生 `/ps`，不是系统级写者审计。

Codex `/ps` 显示无后台终端，`/quit` 后前台只剩 shell。完成门禁的结果发布、
独立验收和宿主收尾均通过；最终 open/waiting_user 为 0。自有观察器和 herdr
服务均已停止，原始失败、事件、动作、处理回执和原生日志保留在本机实验目录。

## 保留的失败与后续

1. **响应时效未通过。** 原生宿主及时拿到了检查点，但控制器的权限往返、
   过期画面重新读取仍耗时；不能用 helper 的 0.601 秒替代端到端审批延迟。
   提交前也有一次 30 秒画面新鲜度检查拒绝，任务尚未发送。应继续在真实项目
   记录发现、动作、确认和记账四个时刻，再决定是否需要宿主通知/调度层改造。
2. **续接不是全程成功。** 初始 120 秒观察器在尚未提交任务时到期，之后重建覆盖
   才提交。表中的提前绑定是后一次接续；它覆盖同一未关闭任务，但业务已发布结果，
   不能当成长期高负载下的连续接续证明。已关闭任务排除由回归覆盖。
3. **原生模型有多余操作。** 首次跨 sandbox PID 查询匹配到包装进程并输出大量文本；
   随后改用原 managed handle 判断。模型还从头重读了一次检查点，最终才用游标
   续读完成。报告引用的 38 ms 是重读已存在标记，不是首次等待延迟。
4. **发布形状仍有差异。** 独立应用测试直接执行 JSON argv；原生模型手写了 shell
   管道调用同一 helper/stdin，路径和结果正确，但未按无 shell 的 recipe 直接执行。
   本轮没有路径修复，不代表任意模型对特殊路径均能正确应用配方。
5. **旧 blocked 由重放回归验证。** 本次原生短实验没有再次出现该状态滞后组合。
   不能将回归通过写成四宿主现场误报全部消失。

用户可开始更新后的真实项目测试，重点记录上述可见表现，尤其是权限是否迟处理、
观察器是否提前接续、结果是否准确落盘及有无额外临时文件。新 space/tab 的名称与
