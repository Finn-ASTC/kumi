## 目标与依据

2026-09-24 后续授权：为方便实际试用 Jev，先交付 AP-01/02 的开发用
[通用影子接口](APPROVAL-SHADOW.md)。明确支持可替换后端，审批流程不绑定 Jev/Laya；
规则、Jev 和独立程序适配器共用输入/结果、预算、失败与恢复记录，分数语义分别保留。
已实现 15 个合成样本的离线演练与协议回归，未调用收费 API。AP-01 仅完成合成试验
身份绑定，真实 run/job/round、租约、期限还未接入；AP-02 未完成真实后端质量评测或
校准。原生控制、连续计量和 30 秒目标仍开放，不因本批交付而关闭。

目标是在保持工程质量和明确授权边界的前提下，减少调度方的大上下文调用、重复验收、
转述和巡视等待，使 agent 可以持续并行工作、合理接班并直接协作。

- [DataHive 反馈](DATAHIVE-FOLLOWUP.md)：按轮验收、取消接管、审批关联、工作流、
  原生身份、共享资源和页面体验等缺口。
- [成本与质量复核](DATAHIVE-COST-QUALITY.md)：长调度会话确有高累计 token，独立验证
  有实际检出价值；现场缺少按轮用量账本，不能推导费用比例或净节省。
- [网状协作提案](MESH-COLLABORATION.md)：同伴消息、委托验证与跨模块协调。
- 本轮新增：Jev/Laya 参与的三级审批，以及人类超时拒绝和向子 agent 反馈的闭环。

成功不是“agent 更多”或“所有审批都自动通过”，而是：同等验收下减少调度调用与等待，
重要缺陷仍能检出，未知与失败仍有记录，恢复时不重复执行、不丢待办。

## 已确定的产品方向

| 方向 | 目标行为 |
|---|---|
| 页面 UX-01 | 新子 agent 默认在已确认的父 space 新建 tab，保留焦点；标题为“任务目的 · agent 类型”，必要时加短编号；续轮复用，space/分屏保留显式选择 |
| 并行工作 | 调度方提交后继续独立工作；巡视和审批有明确负责人，不因等待一个子任务饿死其他任务 |
| 三级审批 | 统一入口核对事实，小模型在既有授权内决定可自动处理的请求，其余交审批协作者；仍需用户决定才开限时窗口 |
| 超时与拒绝 | 到期未获允许则拒绝本次操作；反馈原因和可重提条件，允许补充依据或提出符合授权的替代方案 |
| 验收职责 | 保留独立验证；机械门禁由工具执行，验证者负责明确模块，调度方集中处理冲突、证据完整性、必要抽查和集成 |
| 阶段接班 | 作者或调度方可在已授权范围与预算内发起后继实例接班，携带精简交接包和可回查证据 |
| 网状协作 | 同伴直接问答，作者与验证者直接跟进，模块间按需协作；任务归属与终端输入控制权仍明确 |
| 通知与恢复 | 尽量选择合适时机，允许工作中断；唤醒后由接收方检查未决执行、自主读消息或延期并恢复，未知结果不盲目重跑 |
| 接入边界 | 保持公开项目独立于个人 vault；默认使用原版宿主，不以本体补丁为前提；实验与运行包分开 |

“多数自动、少数协作者、极少数人类”是期望体验，不是预先承诺的比例。
“操作看起来安全”与“已经获得相应授权”分别核对；不通过提高放行率指标驱动越权。

## 批次与依赖

批次表示可评审、可验证的交付单位，不是日历承诺。每批先做确定性验证，再做有限现场
验证；通过后才扩大范围。成本与质量基线从第 0 批开始采集，不等全部功能完成才计量。

| 批次 | 交付内容 | 对应编号 | 完成条件 |
|---|---|---|---|
| 0：计量与基线 | 启动时登记角色/原生来源，检查点采集、缺失提示、阶段汇总；固定成本/质量/审批样本与基线 | CQ-01、D/F08、DH-06 基础 | 调度方、作者、验证者、重试及已发现原生子来源都在清单；未知不作零，重导不重复计数 |
| 1a：按轮验收（已交付） | 历史验收查询/补记、切轮检查，区分业务拒收、协议结果和宿主收尾 | DH-01 | 旧轮补记不改当前轮、不冒充当时已验收；blocked/error 的合法续轮仍可用；[验证](DH1-ROUND-ACCEPTANCE.md) |
| 1b：控制与资源基础 | 审批精确关联、取消/停止确认/接管、watch 接续、输入版本与构建测试资源占用 | DH-02/03/04/07 | 旧控制器、过期事件、并发写入、观察失败均有明确出口；不盲发输入、不伪记解决 |
| 1c：页面体验 | 同 space 默认 tab、任务＋agent 类型标题、焦点和清理归属 | UX-01、F01 | 示例/运行工具/runner 一致；真实 viewer 验证重名、续轮和 no-focus |
| 2a：审批决策层 | 统一审批契约、规则基线、可替换后端、影子判断与校准 | AP-01/02 | 不执行的历史/合成回放可复现；缺信息、超长输入、后端失败不被判成允许 |
| 2b：三级审批闭环 | 持久审批队列、协作者委托、人类计时窗口、宿主批准/拒绝、反馈与有界重提 | AP-03/04/05/06，B/F04/F10 | 先在模拟目标跑通全部分支，再按宿主逐个启用已验收类别；实际动作与解决证据齐全 |
| 3a：验收分工 | 风险分层、轻量报告验收、早期契约检查、模块验证委托、问题聚合与停止条件 | CQ-02/04/05、DH-05、M2 的职责部分 | 历史代表缺陷仍被检出；减少重复模型审阅，不扩大未验证声明 |
| 3b：阶段接班 | 固定交接包、后继只读准备、控制权/监督交接、取消恢复与预算 | CQ-03 | 作者和调度方各有演练；有未决审批和活跃子任务时也不丢身份/待办、不双重输入 |
| 4a：同伴消息 | 独立分支的成员目录、文件消息、短通知、延期/回复/恢复与通知时机 | M0/M1 | 两类宿主实际收发并自主安排读取；持久化、注意、读取、解决分开；旧消息不驱动新实例操作 |
| 4b：网状协调 | 作者↔验证者返工协调、跨模块接口决策、依赖与冲突处置 | M2/M3/M4 局部协调 | 不用调度方逐条转述即可完成有界协作；验收仍绑定版本，循环等待能升级 |

仍须满足切轮、授权与资源门槛。批次不是让所有工作串行等待全部前置的大重写。

## 三级审批的实施规格（AP-01–AP-06）

### AP-01：统一请求与决策契约

所有可识别的原生权限请求进入共同入口；普通问题、登录、信任确认和未知界面先分类，
不能默认当作可自动批准的工具权限。现有 `watch.py` 继续只读，`reviews.py` 继续记录事实；
新增执行职责单独承载，不偷偷让观察器开始发键。

审批记录至少关联：run/job/round、原生会话及操作 ID（可得时）、watch/seq/issue、
精确终端资源、完整操作/参数/cwd、授权策略版本、证据指纹、观察时间、责任人与期限。
请求内容或权限范围改变即需新决策。模型/提示词版本、截断状态、结论、分布与耗时留痕，
不将不存在的模型推理文字编造成解释。

决策记录与动作记录分开：`allow / deny / escalate` 是决策，提交动作、动作不确定、
确认允许、确认拒绝、已失效是执行事实。人类未回应记 `timed_out`，不写成用户明确拒绝；
本次操作按超时策略拒绝。具体 schema 在实现前固定，当前字段仅表达职责。

### AP-02：规则与小模型

- 程序负责能准确计算的身份、权限范围、时限与规则匹配；复杂命令解析失败不套用
  字符串前缀/子串白名单。整条操作的作用域不能由某个安全子命令代替。
- 小模型接受最少而充分的可信授权背景、完整操作与标记为数据的请求理由；回答
  边界清楚的问题。符合限定策略的结果可以直接进入批准执行，其他进入协作者。
- 用 kumi 自有契约衔接规则基线与可选后端，具体次序见[选型报告](APPROVAL-MODEL-SELECTION.md)。
  Jev 固定版本、本地 Laya 多语言版、Von 英文子集和待核查的 DeepSeek 报告配置均为
  候选；先审报告原始证据，再选择一项具备复现条件的影子对照，Foq 先补证据与部署审查。
  记录权重/语言/实际输入、重试与资源成本；接口兼容不证明置信度同义。
  未配置或失败时正常升级复核，默认不同时调用所有候选，不把本地失败自动转成远端外发。
- 阈值按任务与宿主样本校准，不直接照搬 `0.95`；识别不完整、超长/截断、输出畸形、
  服务超时或不可用都不得转成自动允许。模型概率也不能覆盖明确拒绝规则或新增授权。
- 先影子运行：只记录建议与既有结果对照；再启用通过验收的授权类别。Jev 远端评估
  使用合成/脱敏数据；真实项目证据是否外发必须是明确的运行配置，不因接入 API 自动外发。

### AP-03：审批协作者

为审批设明确职责与有限上下文，可复用专门实例，不必每次启动新 agent。
派给它的是当前操作、任务/授权摘要、小模型结论、缺失信息和相关历史，不是全部项目转录。
它可在已有委托范围内批准或拒绝；缺用户授权/偏好才上报人类。它不能把自己对风险的
判断当成用户新增授权，也不能通过发消息给作者转移原生权限。

审批服务接收结构化复核结果，由唯一输入执行方执行；协作者不和调度方争抢终端。
协作者不可用、过期或自身遇到权限阻塞时升级，不递归创建无限审批 agent。
定义协作者响应预算、总待办年龄、公平队列和并发上限；不让一个请求拖住其他子 agent。

### AP-04：人类限时窗口

窗口显示任务/agent、完整操作及可展开详情、目标位置、上报原因、有效期限，提供
“允许本次 / 拒绝本次”。默认不授予永久权限，不强行切换到子终端；允许显式查看证据。
计时从确认窗口已展示开始，同时设置独立的展示失败/总请求期限，避免无人可见的无限等待。
秒数先做 run 配置，使用短时模拟测试竞态；实际默认值在体验试验后确定。

到期未获允许按用户提出的策略拒绝本次操作。关闭窗口按拒绝本次处理，并记录关闭来源；
窗口显示失败单独记录，不冒充人类看过。到期、点击、任务取消通过同一版本检查提交，
只能产生一个生效决定；迟到点击、重复通知和恢复后的旧窗口不能批准新操作。
重启后保留原截止时间，不因重启重新给一整段倒计时；没有 GUI 时使用可用的审批界面，
若无法呈现则走展示失败的有界处置，不能自动允许。

### AP-05：宿主执行与持久服务

定义宿主级 `approve_current` / `deny_current` 能力；优先使用带操作 ID 的公开接口，
其次采用已实测的精确 UI 选项。**不把所有超时拒绝实现成 Esc**：Esc 在不同界面可能
关闭选择器、打断整轮或没有完成中断。发键前重读目标，操作后验证请求已按预期解决。

服务是显式启动、可停止、有健康状态的 run 级后台组件，使用持久队列；后续可选托管，
不默认改系统启动项。模型暂时不参与巡视也能处理已授权类别；服务死亡时保留待办并
显示监督缺口，不能宣称仍在监控。队列执行按目标串行，跨目标可并行；租约、重启、
丢回执、取消和控制器接班都要恢复。

同一时刻每个目标只有一个输入执行方。现有本地租约不能阻止绕过 helper 的任意终端
输入；纯 TUI 的读屏和发键之间也不是原子操作。没有足够身份或窗口稳定性时保留
未解决状态并升级，不宣称严格 exactly-once 或绝对可靠的自动点击。

### AP-06：拒绝、反馈与重提

确认拒绝后，告诉作者：拒绝来源（策略/协作者/人类/超时）、必要依据或缺失信息、
允许的替代范围。作者可以补充新事实、缩小操作范围或选择无需该权限的办法。
主动拒绝不能被简单改写理由绕过；超时不意味着操作已被判有害，但也不是允许。

同一操作绑定原请求和前次决策；语义未变、没有新依据的重提不反复弹窗。
配置单问题重提次数、冷却与总预算；耗尽后保持 blocked 并给负责人明确结论。
替代方案仍须符合相同授权边界，不通过换工具规避原拒绝。
拒绝后先确认宿主输入就绪再反馈；若已有有效 result，依现有协议用新轮次推进，
不改旧结果。拒绝一个操作与取消整个 job 分别记账。

## 验收、接班和协作的交付要求

### 验收分工

任务开始即列出风险、独立检查负责人、spec/oracle 版本和覆盖缺口。高风险包括状态机、
外部输入、并发、数据一致性、跨模块接口及 CLI→运行时接线，尽量提前验证。
低风险修改采用针对性检查；不是每轮都强制三/四预设完整重构建，也不机械取消必要门禁。

验证者可先准备独立夹具，最终针对作者固定快照给出结论；模块验收授权与输入控制权
分别委托。调度方不逐条重复验证者工作，但保留证据审阅、争议处理、必要抽查和集成门禁。
验证者修改实现后，受影响部分须另有独立复验。问题按根因/契约聚合，明确本轮停止条件、
延期理由和下一负责人，避免无限猎错。旧失败、重试与标准变更保留。

### 阶段接班

作者和调度方都可提出接班。第一版做显式边界接班，后续根据实际上下文、压缩效果、
预算和进展决定是否自动触发；无需以无限增加委派深度来表达同一职责的替换。
后继只读准备 → 核对交接包 → 旧方停止输入 → 明确交接控制和监督 → 后继接续。

交接包含任务/授权、版本/工作树/未提交产物、决策及理由、结果与未覆盖项、活动子任务、
审批与 uncertain 状态、预算和下一步。历史证据按需回查，不默认复制全部会话；不让
小模型直接删除不可恢复的历史。演练时注入交接中崩溃、旧方迟到输入、审批窗口未关闭、
子任务仍运行等场景。接班失败可恢复，旧实例不能凭猜测重新夺回控制权。

### 网状协作

首版限同机同 run。成员查询、定向消息、回复关联、读确认和问题解决分别记录；
精确身份不靠 tab 名称；增量读取和按需证据避免全员广播完整历史。
消息持久化不意味着模型被唤醒：工作检查点读取、宿主可用通知、下一轮衔接分别适配。

M0/M1 后续单独分支实验采用用户明确的“文件正文＋终端短通知”：受控通知只让

正文已读、延期和处理完成分别记录，积压合并通知。具体约束见[协作提案](MESH-COLLABORATION.md)。

launch/submit 门禁、精确 identity pin、控制/通知分类记录，以及 startup metering
plan/checkpoint。`tests/control_lab_demo.py` 在独立目录用四类宿主的合成来源，覆盖五种配置，
演练注册、冲突、重启导入、未知控制器覆盖和显式释放。错误输入、部分初始化、旧身份、
证据改写和竞态已进入回归。它们都是 `tests/` 开发/验收工具，不随运行 skill 分发，也
不向终端发键。资源预留是合作式锁，不是 OS 级文件/端口隔离；控制器崩溃不会自动释放。
启动过的 job 仍由既有停止/完成门槛收尾。

下一个实测单元应使用四类宿主经核对的现有配置、显式宿主版本/UI 模式和精确 native
session ID，逐项填写 deny、stop、idle notice、interrupt-and-resume notice。真实对象开始前
先用 sandbox 夹具及不影响工作的自有目标确认动作门槛。初始计量计划刻意为空，显示未绑定
与未知；演练用合成 JSONL/SQLite 只检查导入器，不能冒充实际 token。首份真实计量须来自此次 run
明确绑定的日志和 request/attempt，覆盖率在报告中展示。

实验分支已实现 M0 成员目录，消息契约仍待做，main 未包含实验代码。目录在同一 run 登记稳定 member ID、job/round、agent
实例/native session、角色/模块、职责摘要、消息范围、输入/监督/验收负责人及 lifecycle；
tab 名称只用于显示。查找按模块/职责和有效实例过滤，过期/替换成员不能静默接收旧消息；
目录不得公开租约 token 或越权日志。成员可见性先于消息路由，消息读写授权独立于任务写权。
共同基础在 main；成员目录仅在实验分支，不代表 M1 消息上线。

### 2．尽早验证用户的文件消息＋短通知

2a 先固定独立版本的成员/消息 sidecar，绑定 run/job/round/实例，与 request/result v1
分开。最小入口涵盖发送、摘要/正文读取、注意确认、延期、回复和解决；入口名字在
实现时定，不在本计划伪造可用命令。消息先落盘、发送方即继续工作，终端只投递：

```text
[kumi消息] 来自=存储验证者 优先级=普通 主题=接口参数确认 id=m-1042
```

优先级和主题帮助接收方安排，接收方可以不读正文先标记待办，继续原任务；读后也
可以延期。注意/已读/延期/处理分别保存，重启/上下文压缩后仍可找到；不强制每条
消息回复“收到”。标记不提升消息权限，不覆盖用户任务、原审批或已发布结果。

2b 的投递器显式启停、有健康状态和恢复入口，不靠调度大模型轮询等待。所有同伴
通过共同工具发消息，每个目标只有一个输入执行方，审批与普通通知竞争输入时由
同一所有者串行协调。先做新鲜证据下的空闲/已验证原生排队通知，再验证
“选择合适时机中断→确认输入就绪→输入通知并回车→接收方检查并自行安排恢复”。
普通消息也可及时通知，不要求等整个任务结束。选时用于减少干扰，不承诺零中断；
接收方检查实际执行状态后接续，按[恢复约定](DECISION-LAYER-FOLLOWUP.md)
处理未知结果。身份/输入界面等必要事实无法确认时留队并显示原因和期限，不靠模型概率盲发。

不误触审批/选择器、不丢已有草稿、不向已退出 CLI 的 shell 发送、不错投后继实例；
保存通知前后的业务位置、工具/后台状态和接收回执。多发送方突发时合并摘要，
接收方延期后有界提醒，不能每次扫描都中断。通知提交成功、模型注意到通知、正文
读取和问题解决分别测量；投递器死亡时报告监督缺口，不能声称仍在自动投递。

首个小项目限定调度方＋作者＋验证者，四类宿主按角色轮换异构组合，调度方持续做
独立工作。验证普通消息延期后继续、相关接口消息提前读取、两个发送方并发、
重复/旧轮/接收方退出、待审批时保留队列、投递器重启、不确定投递核查。
先直接消息问答，不立即让同伴自动切轮或取得终端控制权。

可替换模型判断通知机会放在后续同场景对照里；它与审批分类使用不同标签、
校准和验收，不能仅因审批准确就用于判定中断安全。事件触发＋有限次数复核，
不按每秒截图调用模型。记录消息可见/实际处理延迟、原工作进展、丢失工具、额外
唤醒与恢复 token。先有不用该模型的基线，才知道增加判断是否有益。

**合并门槛：** 独立失败用例未出现错对象输入/误审批/丢消息，接收方实际完成延期
与后续处理、仍能完成原任务；已知限制写入能力表。只合并验收过的可选路径，
关闭后回到现有显式转述方式，保留待办与证据。需要未支持的中断方式时继续保持实验。

### 3．审批链路与模型后端分别推进

AP-01 先固定请求、决定、期限和操作证据；AP-02 建规则与协作者基线以及离线回放。
模型只输出建议，动作由已有授权与精确执行层控制。缺模型时流程也能工作。

Jev 在[选型报告](APPROVAL-MODEL-SELECTION.md)中仍是有条件的首轮云端候选：实际
使用地区的账号/鉴权、访问线路、延迟、限额、数据处理和支付可用性逐项核对。
注册说明或一次 DNS/HTTP 成功不能证明国内稳定可用；当前没有完成该环境下的
鉴权压力测试。不得默认为实测直连，也不让这项阻塞文件通信、规则或模拟审批。
真实调用使用明确配置与预算，先用合成数据；不在规划阶段开户、付费或上传私人材料。

本地 Laya 多语言版、Von 英文子集按既定计划比较；Foq 保留观察，避免同时部署全部
候选。固定模型/样本/阈值/预算，缺项和超长输入保持升级，先以误放行约束比较覆盖
与总成本。小规模样本先查协议缺陷，500–1000 例问题发现集及独立保留集分开准备，
不将零观察错误换算为普遍安全；国内可用性与中文判断质量是两项独立验收。
以上是既有候选范围；报告审计后优先选择一个有完整复现条件的适配器，不要求逐一
安装所有候选。DeepSeek 的报告结果待核对，不直接采用 0.05、命令前缀白名单或
首块延迟作为审批质量/完成证据；接口契约保留供应商无关性。

AP-03–06 先用确定性目标走完整队列：既有授权内自动决定→审批协作者→必要时人类
窗口；展示确认后计时，另设展示失败期限；超时拒绝本次操作、反馈、有限重提。
决定与执行分开，服务重启、旧窗口点击、取消竞态、断网和委托超期均可恢复。
在人类入口研究 V-03 Hermes 原生 transport；不把它的人类回答契约冒充模型许可。
之后只为已经核对的宿主/操作类别加入真实批准、拒绝与动作确认，其余保持升级。

### 4．先减少重复审核，再实现有界接班

CQ-02/04/05 与 DH-05 可以在消息原型期间提前交付轻量报告验收和按风险的检查计划；
保留独立验证、原始失败和版本化证据，避免每轮机械全量构建。验证者承担明确模块，
调度方看必要证据、冲突和集成结果，不逐条复述同伴问答。

消息路径稳定后做 M2 作者↔验证者的一次缺陷复现、固定快照拒收、新轮修复与复验。
M3 再加入第二模块接口依赖和资源冲突；不从全连接团队开始。没有显式委托时，
验收记账、切轮与输入权限仍由原负责人掌握。

CQ-03 第一版采用显式接班：后继只读准备精简交接包→旧方停止输入→原子记录／
核验控制及监督交接→后继接续。包内包含未提交工作、决定、未读/延期消息、待审批、
uncertain 动作、活跃子任务与预算。分别演练作者和调度方接班；通知或接班失败不
重复业务，也不丢原待办。先不按固定 token 阈值自动换实例，不假设新会话一定更便宜。

### 5．带着证据选择默认策略，再进入实际项目复测

CQ-01 连续计量贯穿全部阶段；H4/V-02 在独立 checkout/profile 测上游原生辅助 hook，
仍不改日常 Hermes 本体。未覆盖来源保持未知，不阻塞已有可解释子集实验，也不能
在两组计量覆盖不同的情况下声称总成本胜出。

E/CQ-06 固定同一小项目、种子、oracle、宿主/模型配置与运行预算，先建立现状基线，
分次只引入消息、通知中断、小模型判断、委托验收或接班中的一项；不要同时打开
所有功能再笼统比较。至少重复运行并保留失败，计入调度、作者、验证、模型判断、
后台、重试和恢复；同时报告质量、等待、p50/p95 延迟与不确定覆盖。

成果验收后再交给用户做真实项目体验：默认仍同 space 新 tab、任务＋agent 标题、
保留焦点。反馈重点为是否打扰工作、积压是否可见、审批是否及时、接班是否丢信息，
而不是要求用户替开发补基础协议测试。30 秒审批响应目标尚未达标，独立复测。

每批提交包括实现/对应测试/能力边界/状态更新；运行代码变更做相关回归，公共
控制改动跑完整回归及分发检查，纯文档改动做差异与链接检查即可。合并实验前重跑
相关真实宿主和干净安装验证。开源发布继续核对远端 CI、运行包自包含、许可证与
隐私；升级宿主、安装同步、推送/发布分别按实际授权执行，不由实验成功自动触发。
