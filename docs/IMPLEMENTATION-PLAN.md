# kumi 综合实施计划

日期：2026-09-23。实现基线：`c5788a6`。
**状态：分批实施中。CQ-01 的显式计量工具闭环已交付，其余能力按下表推进。本文统一执行顺序；专题文档保留证据和细节。**

2026-09-23 进展：[CQ-01 最小计量闭环](CQ1-METERING.md)已增加不可变计量计划、

## 目标与依据

目标是在保持工程质量和明确授权边界的前提下，减少调度方的大上下文调用、重复验收、
转述和巡视等待，使 agent 可以持续并行工作、合理接班并直接协作。

- [DataHive 反馈](DATAHIVE-FOLLOWUP.md)：按轮验收、取消接管、审批关联、工作流、
  原生身份、共享资源和页面体验等缺口。
- [成本与质量复核](DATAHIVE-COST-QUALITY.md)：长调度会话确有高累计 token，独立验证
  有实际检出价值；现场缺少按轮用量账本，不能推导费用比例或净节省。
- [网状协作提案](MESH-COLLABORATION.md)：同伴消息、委托验证与跨模块协调。
- 本轮新增：Jev/Laya 参与的三级审批，以及人类超时拒绝和向子 agent 反馈的闭环。

成功不是“agent 更多”或“所有审批都自动通过”，而是：同等验收下减少调度调用与等待，
重要缺陷仍能检出，未知与失败仍有记录，恢复时不重复执行、不丢待办。

## 已确定的产品方向

| 方向 | 目标行为 |
|---|---|
| 页面 UX-01 | 新子 agent 默认在已确认的父 space 新建 tab，保留焦点；标题为“任务目的 · agent 类型”，必要时加短编号；续轮复用，space/分屏保留显式选择 |
| 并行工作 | 调度方提交后继续独立工作；巡视和审批有明确负责人，不因等待一个子任务饿死其他任务 |
| 三级审批 | 统一入口核对事实，小模型在既有授权内决定可自动处理的请求，其余交审批协作者；仍需用户决定才开限时窗口 |
| 超时与拒绝 | 到期未获允许则拒绝本次操作；反馈原因和可重提条件，允许补充依据或提出符合授权的替代方案 |
| 验收职责 | 保留独立验证；机械门禁由工具执行，验证者负责明确模块，调度方集中处理冲突、证据完整性、必要抽查和集成 |
| 阶段接班 | 作者或调度方可在已授权范围与预算内发起后继实例接班，携带精简交接包和可回查证据 |
| 网状协作 | 同伴直接问答，作者与验证者直接跟进，模块间按需协作；任务归属与终端输入控制权仍明确 |
| 接入边界 | 保持公开项目独立于个人 vault；默认使用原版宿主，不以本体补丁为前提；实验与运行包分开 |

“多数自动、少数协作者、极少数人类”是期望体验，不是预先承诺的比例。
“操作看起来安全”与“已经获得相应授权”分别核对；不通过提高放行率指标驱动越权。

## 批次与依赖

批次表示可评审、可验证的交付单位，不是日历承诺。每批先做确定性验证，再做有限现场
验证；通过后才扩大范围。成本与质量基线从第 0 批开始采集，不等全部功能完成才计量。

| 批次 | 交付内容 | 对应编号 | 完成条件 |
|---|---|---|---|
| 0：计量与基线 | 启动时登记角色/原生来源，检查点采集、缺失提示、阶段汇总；固定成本/质量/审批样本与基线 | CQ-01、D/F08、DH-06 基础 | 调度方、作者、验证者、重试及已发现原生子来源都在清单；未知不作零，重导不重复计数 |
| 1a：按轮验收 | 历史验收查询/补记、切轮检查，区分业务拒收、协议结果和宿主收尾 | DH-01 | 旧轮补记不改当前轮、不冒充当时已验收；blocked/error 的合法续轮仍可用 |
| 1b：控制与资源基础 | 审批精确关联、取消/停止确认/接管、watch 接续、输入版本与构建测试资源占用 | DH-02/03/04/07 | 旧控制器、过期事件、并发写入、观察失败均有明确出口；不盲发输入、不伪记解决 |
| 1c：页面体验 | 同 space 默认 tab、任务＋agent 类型标题、焦点和清理归属 | UX-01、F01 | 示例/运行工具/runner 一致；真实 viewer 验证重名、续轮和 no-focus |
| 2a：审批决策层 | 统一审批契约、规则基线、Jev/Laya 可选适配、影子判断与校准 | AP-01/02 | 不执行的历史/合成回放可复现；缺信息、超长输入、后端失败不被判成允许 |
| 2b：三级审批闭环 | 持久审批队列、协作者委托、人类计时窗口、宿主批准/拒绝、反馈与有界重提 | AP-03/04/05/06，B/F04/F10 | 先在模拟目标跑通全部分支，再按宿主逐个启用已验收类别；实际动作与解决证据齐全 |
| 3a：验收分工 | 风险分层、轻量报告验收、早期契约检查、模块验证委托、问题聚合与停止条件 | CQ-02/04/05、DH-05、M2 的职责部分 | 历史代表缺陷仍被检出；减少重复模型审阅，不扩大未验证声明 |
| 3b：阶段接班 | 固定交接包、后继只读准备、控制权/监督交接、取消恢复与预算 | CQ-03 | 作者和调度方各有演练；有未决审批和活跃子任务时也不丢身份/待办、不双重输入 |
| 4a：同伴消息 | 成员目录、定向消息、增量收件箱、答复/失效/恢复与宿主检查点 | M0/M1 | 两类宿主实际收发；持久化、读取、解决分开；旧轮消息不驱动新轮操作 |
| 4b：网状协调 | 作者↔验证者返工协调、跨模块接口决策、依赖与冲突处置 | M2/M3/M4 局部协调 | 不用调度方逐条转述即可完成有界协作；验收仍绑定版本，循环等待能升级 |
| 5：对照与默认策略 | 集中审核、委托审核、接班、同伴消息、三级审批的受控对照 | CQ-06、E/F11 | 相同任务/基线/验收及明确模型配置，多次运行保留失败；按质量、用量、延迟和覆盖选择默认值 |

第 1c 批不依赖模型接入，可以提前单独交付。第 2a 批的离线设计/回放不依赖第 1b 批
全部完成；真实输入执行依赖相关控制门槛。第 3a/3b 批不必等待完整三级审批或网状消息：
相关基础成立后即可做显式交接与委托演练。第 4a 批限定问答可独立原型化，自动返工
仍须满足切轮、授权与资源门槛。批次不是让所有工作串行等待全部前置的大重写。

## 三级审批的实施规格（AP-01–AP-06）

### AP-01：统一请求与决策契约

所有可识别的原生权限请求进入共同入口；普通问题、登录、信任确认和未知界面先分类，
不能默认当作可自动批准的工具权限。现有 `watch.py` 继续只读，`reviews.py` 继续记录事实；
新增执行职责单独承载，不偷偷让观察器开始发键。

审批记录至少关联：run/job/round、原生会话及操作 ID（可得时）、watch/seq/issue、
精确终端资源、完整操作/参数/cwd、授权策略版本、证据指纹、观察时间、责任人与期限。
请求内容或权限范围改变即需新决策。模型/提示词版本、截断状态、结论、分布与耗时留痕，
不将不存在的模型推理文字编造成解释。

决策记录与动作记录分开：`allow / deny / escalate` 是决策，提交动作、动作不确定、
确认允许、确认拒绝、已失效是执行事实。人类未回应记 `timed_out`，不写成用户明确拒绝；
本次操作按超时策略拒绝。具体 schema 在实现前固定，当前字段仅表达职责。

### AP-02：规则与小模型

- 程序负责能准确计算的身份、权限范围、时限与规则匹配；复杂命令解析失败不套用
  字符串前缀/子串白名单。整条操作的作用域不能由某个安全子命令代替。
- 小模型接受最少而充分的可信授权背景、完整操作与标记为数据的请求理由；回答
  边界清楚的问题。符合限定策略的结果可以直接进入批准执行，其他进入协作者。
- 同一接口支持规则基线、Jev API 和本地 Laya；均为可选后端，未配置时正常升级复核。
  Jev 固定版本并计入远端输入/延迟；Laya 记录检查点、语言路由、资源消耗与实际输入长度。
- 阈值按任务与宿主样本校准，不直接照搬 `0.95`；识别不完整、超长/截断、输出畸形、
  服务超时或不可用都不得转成自动允许。模型概率也不能覆盖明确拒绝规则或新增授权。
- 先影子运行：只记录建议与既有结果对照；再启用通过验收的授权类别。Jev 远端评估
  使用合成/脱敏数据；真实项目证据是否外发必须是明确的运行配置，不因接入 API 自动外发。

### AP-03：审批协作者

为审批设明确职责与有限上下文，可复用专门实例，不必每次启动新 agent。
派给它的是当前操作、任务/授权摘要、小模型结论、缺失信息和相关历史，不是全部项目转录。
它可在已有委托范围内批准或拒绝；缺用户授权/偏好才上报人类。它不能把自己对风险的
判断当成用户新增授权，也不能通过发消息给作者转移原生权限。

审批服务接收结构化复核结果，由唯一输入执行方执行；协作者不和调度方争抢终端。
协作者不可用、过期或自身遇到权限阻塞时升级，不递归创建无限审批 agent。
定义协作者响应预算、总待办年龄、公平队列和并发上限；不让一个请求拖住其他子 agent。

### AP-04：人类限时窗口

窗口显示任务/agent、完整操作及可展开详情、目标位置、上报原因、有效期限，提供
“允许本次 / 拒绝本次”。默认不授予永久权限，不强行切换到子终端；允许显式查看证据。
计时从确认窗口已展示开始，同时设置独立的展示失败/总请求期限，避免无人可见的无限等待。
秒数先做 run 配置，使用短时模拟测试竞态；实际默认值在体验试验后确定。

到期未获允许按用户提出的策略拒绝本次操作。关闭窗口按拒绝本次处理，并记录关闭来源；
窗口显示失败单独记录，不冒充人类看过。到期、点击、任务取消通过同一版本检查提交，
只能产生一个生效决定；迟到点击、重复通知和恢复后的旧窗口不能批准新操作。
重启后保留原截止时间，不因重启重新给一整段倒计时；没有 GUI 时使用可用的审批界面，
若无法呈现则走展示失败的有界处置，不能自动允许。

### AP-05：宿主执行与持久服务

定义宿主级 `approve_current` / `deny_current` 能力；优先使用带操作 ID 的公开接口，
其次采用已实测的精确 UI 选项。**不把所有超时拒绝实现成 Esc**：Esc 在不同界面可能
关闭选择器、打断整轮或没有完成中断。发键前重读目标，操作后验证请求已按预期解决。

服务是显式启动、可停止、有健康状态的 run 级后台组件，使用持久队列；后续可选托管，
不默认改系统启动项。模型暂时不参与巡视也能处理已授权类别；服务死亡时保留待办并
显示监督缺口，不能宣称仍在监控。队列执行按目标串行，跨目标可并行；租约、重启、
丢回执、取消和控制器接班都要恢复。

同一时刻每个目标只有一个输入执行方。现有本地租约不能阻止绕过 helper 的任意终端
输入；纯 TUI 的读屏和发键之间也不是原子操作。没有足够身份或窗口稳定性时保留
未解决状态并升级，不宣称严格 exactly-once 或绝对可靠的自动点击。

### AP-06：拒绝、反馈与重提

确认拒绝后，告诉作者：拒绝来源（策略/协作者/人类/超时）、必要依据或缺失信息、
允许的替代范围。作者可以补充新事实、缩小操作范围或选择无需该权限的办法。
主动拒绝不能被简单改写理由绕过；超时不意味着操作已被判有害，但也不是允许。

同一操作绑定原请求和前次决策；语义未变、没有新依据的重提不反复弹窗。
配置单问题重提次数、冷却与总预算；耗尽后保持 blocked 并给负责人明确结论。
替代方案仍须符合相同授权边界，不通过换工具规避原拒绝。
拒绝后先确认宿主输入就绪再反馈；若已有有效 result，依现有协议用新轮次推进，
不改旧结果。拒绝一个操作与取消整个 job 分别记账。

## 验收、接班和协作的交付要求

### 验收分工

任务开始即列出风险、独立检查负责人、spec/oracle 版本和覆盖缺口。高风险包括状态机、
外部输入、并发、数据一致性、跨模块接口及 CLI→运行时接线，尽量提前验证。
低风险修改采用针对性检查；不是每轮都强制三/四预设完整重构建，也不机械取消必要门禁。

验证者可先准备独立夹具，最终针对作者固定快照给出结论；模块验收授权与输入控制权
分别委托。调度方不逐条重复验证者工作，但保留证据审阅、争议处理、必要抽查和集成门禁。
验证者修改实现后，受影响部分须另有独立复验。问题按根因/契约聚合，明确本轮停止条件、
延期理由和下一负责人，避免无限猎错。旧失败、重试与标准变更保留。

### 阶段接班

作者和调度方都可提出接班。第一版做显式边界接班，后续根据实际上下文、压缩效果、
预算和进展决定是否自动触发；无需以无限增加委派深度来表达同一职责的替换。
后继只读准备 → 核对交接包 → 旧方停止输入 → 明确交接控制和监督 → 后继接续。

交接包含任务/授权、版本/工作树/未提交产物、决策及理由、结果与未覆盖项、活动子任务、
审批与 uncertain 状态、预算和下一步。历史证据按需回查，不默认复制全部会话；不让
小模型直接删除不可恢复的历史。演练时注入交接中崩溃、旧方迟到输入、审批窗口未关闭、
子任务仍运行等场景。接班失败可恢复，旧实例不能凭猜测重新夺回控制权。

### 网状协作

首版限同机同 run。成员查询、定向消息、回复关联、读确认和问题解决分别记录；
精确身份不靠 tab 名称；增量读取和按需证据避免全员广播完整历史。
消息持久化不意味着模型被唤醒：工作检查点读取、宿主可用通知、下一轮衔接分别适配。

作者与验证者直接复现/跟进；模块同伴直接讨论接口和依赖。普通问答不需调度方批准，
改变契约/写入范围/验收标准时交相应负责人。聊天不自动取得终端控制权或其他任务的
取消权。写入/测试资源冲突显式协调，真实依赖循环要有期限与裁决者。

## 验证矩阵与指标

| 层次 | 验证内容 | 通过要求 |
|---|---|---|
| 确定性协议 | 旧事件、新弹窗、重复/乱序、服务重启、审批超时与点击竞态、丢回执、切轮、取消与交接 | 已知测试集中无误放行/错对象动作；不确定副作用保留不确定，不伪造完成 |
| 宿主适配 | Codex、omp、Hermes、OpenCode pure/OMO 的明确版本与配置；允许、拒绝、超时、拒绝后继续 | 每个已支持组合有真实证据；不支持的组合明确降级，不能拿一种宿主结果覆盖全部 |
| 决策质量 | 原规则、规则＋Jev、规则＋Laya；正常与风险样本、中文/混合语言、长命令、缺信息与对抗正文 | 分开统计错误放行、误拒绝、漏检、升级率；阈值校准与保留评测集分离，零样本误放行不是风险为零的证明 |
| 工程质量 | 历史缺陷族、负对照、跨模块集成、验证装置偏差、同族问题聚合 | 代表性缺陷仍被检出；准确列出未覆盖项、缺陷修复及复验成本 |
| 接班与消息 | 活跃子任务/未决审批下接班、离线接收方、旧轮消息、循环等待、取消传播 | 不双重输入、不丢责任、不重复启动返工；后继可从证据恢复 |
| 产品体验 | 同 space tab、可识别标题、焦点保留、限时窗口、重复弹窗与关闭/超时反馈 | 用户能看清是谁请求什么；过期窗口无效，后台活动不抢终端焦点 |

计量维度：输入（缓存子集与非缓存分别展示）、输出、来源覆盖、模型调用数、审批/验证/
交接/返工阶段；延迟记录发现→分类→协作者→窗口展示→人类决定→动作→确认；另计 CPU/
构建时间、等待、接管次数和漏掉的监督窗口。既有 30 秒审批响应目标继续保留，自动路径、
协作者路径与人为等待分别报告，不能将推理 100ms 冒充端到端审批 100ms。

对照分步改变单个因素：先比集中与委托，再比继续/压缩/接班，再加同伴消息与审批后端。
用同一任务种子和验收标准，固定模型配置，重复运行并保留失败。完整质量相当时再讨论
节省；缓存 token 不直接乘普通输入价格，费用注明来源/价格版本，未知不补估算。
宿主全量计量未就绪时可选覆盖可解释的子集，不因此无限推迟 E。

  做破坏性回放。优先合成 fixture，再用脱敏现场形状，再进行限定原生实验。

  改默认。本计划不授权部署远端服务、公开私人证据或自动推送 GitHub。
