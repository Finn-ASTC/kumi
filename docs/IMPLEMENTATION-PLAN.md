## 2．目标体验与固定约束

1. **容易使用和找回。** 新 worker 默认同 space 新 tab、不抢焦点；标题说明任务与
   agent 类型。主会话易找，worker 按 run 收纳；直接打开宿主的历史列表也单独验收。
2. **调度方持续工作。** 提交后推进自己的任务；工具承担机械等待、队列和提醒，
   调度模型集中处理异常、冲突与集成，不能因为一个子任务长时间占住而漏掉其他审批。
3. **同伴自主沟通。** 同机同 run 的获准成员互相可发现，正文落盘，终端只给发送方、
   优先级、主题和 ID。普通问答不经调度方逐条转述，也不等整个任务结束才通知。
4. **可以延期，不能静默遗忘。** 入队即有未读责任，延期有时间/检查点和上限，
   到期工具跟进、超期升级、交付前明确处置；服务死亡时暴露覆盖缺口。
5. **允许受控打断，认真恢复。** 接收方核查原工作和未决工具后续做；不宣称绝对安全，
   不向审批框/用户草稿/错误实例/shell 盲发，也不因回包缺失重放副作用。
6. **审批可分流且可替换。** 已有授权内规则/可选模型 → 审批协作者 → 必要人类窗口；
   超时拒绝本次操作并反馈。通知选时、审批授权采用不同契约，服务商不成为核心依赖。
7. **保留工程质量。** 作者与独立验证者职责明确，调度方保留集成和必要抽查；
   结果、验收和返工绑定版本，不为少花 token 省掉必要验证。
8. **会话与职责可接班。** 显式移交未提交工作、消息、审批、子任务和监督；
   原生历史恢复不自动复活旧 job，新实例不能按同名继承旧输入权限。
9. **宿主平等。** Codex、omp、Hermes、OpenCode OMO/pure 共用协议、角色和验收；
   适配能力分别报告，缺证据写未测，不固定某一宿主为主、其他为次。
10. **可携带与可度量。** 不依赖个人 vault、不改宿主本体；六个 skills 自包含，
    runner/评测/私有日志单独存放；只在同等质量及可解释计量覆盖下比较实际成本。

范围先限定本机已知参与者、单条消息一个精确接收方、合作式所有权。跨机器消息、
全连接广播、默认自动开无限 agent、会话自动删除、完整 GUI、强制 OS 隔离和完全无人
值守不进入首轮。不因一项实验成功就自动安装、改默认、升级宿主或推送发布。

## 3．共用基础与职责边界

| 层 | 复用 / 新增职责 | 必须保持的边界 |
|---|---|---|
| 任务事实 | 复用 protocol/jobs/runs/round_history/completion | request/result v1 严格校验；新增可选 sidecar 独立版本与精确绑定 |
| 会话与成员 | M0 负责获准成员；UX-02 记录原生 store/profile/session、项目/run/角色与可见性 | 会话目录是派生视图；昵称、标题、cwd、最近时间都不是身份 |
| 消息责任 | M1 正文、回执、延期/业务责任、转交和交付截止水位 | 入队即有未读；提交、返回正文、理解声明、回复和解决分开 |
| 监督调度 | 复用观察/租约/审计，新增提醒和审批持久队列 | watch 保持只读；机械循环不调用模型；异常有负责人和期限 |
| 输入执行 | 每目标一个当前控制方协调通知、审批和停止 | 同目标串行，跨目标可并行；锁外做终端/网络 I/O，uncertain 先对账 |
| 宿主适配 | herdr/原生通知、可选 hcom、会话隔离/归档、审批动作 | 不静默换通道；notify ≠ stopped；归档 ≠ 退出；ACK ≠ 已读 |
| 判定后端 | 规则、可选 Jev/Laya/Von/报告候选等的适配与预算 | 不共享概率阈值，不把传输后端 hcom 和判定模型混为一层 |
| 质量与用量 | 固定快照、独立验收、实际来源/阶段采集和不可变纠正 | 保留失败/未知；归档/接班不丢证据，也不重复计费 |

新增常驻能力先是**显式启动、有截止时间和健康记录的 run 级进程**，不是系统服务。
提醒与审批可以复用调度/幂等/重启模式，但保留各自队列、权限和状态，不先写一个
覆盖所有业务的大框架。没有存活监督方时保留状态并在恢复时报警，不虚构唤醒保证。

### 不同功能的依赖，不用整个阶段互相卡住

| DH-02/03/F10：控制、预算、接管 | 阶段 4–6，阶段 8 再验交接 | 原生拒绝、取消、超时预算、旧续租、后台/迟到副作用、宿主死亡、blocked 续轮、watch 换代可恢复 |
| DH-04/06/07：工作流、身份、资源 | 阶段 2 定位，4 启动，7/9 委托扩展 | 降低手写现场脚本；真实身份与 spec 可见，工作树/构建目录/端口/DB 冲突显式，污染后干净复验 |
| D/H4/V-02：完整计量 | 阶段 4 固定缺口；5 起独立适配小批；10 前检查比较范围 | 上游原生辅助观察器优先，不恢复宿主补丁；流式/重试/后台/退出 flush/父子与跨 job 重叠可核对 |
| B3：保留历史完整性 | 阶段 3 审阅账本设计；阶段 6 若增加强保证则单独实现/故障测试 | 现有 review 删尾可能回到旧状态，持续标未知；新消息账本不自动修复旧 review 链，不承诺防任意回滚 |
| V-01–04：版本漂移 | 每次原生实验前；宿主升级后、可选发布前 | binary/配置/daemon/UI 模式分别固定；本轮 omp 18.3.0 仅有帮助证据；不能借旧测试自动放行新版本 |
| F01/F10：页面、结果落点与长期恢复 | 阶段 4/5/8 及实际项目复测 | 焦点、标题截断、准确发布 argv、额外写入、PID 观察边界、原生故障组合有单独证据 |
| 开源和运行包 | 每次 runtime 变更；阶段 10 | 最小复制运行、离线检查、实际 skill 发现、许可/隐私和远端 CI 各自通过，不借源码测试代替 |

H2 原生接口提案仍未对外提交；若上游当前接口足够，先实现其可选 adapter。
外部提案/安装更新/真实后端账户有独立范围，不是推进本地文件与模拟工作的前提。
C1/C2 恢复摘要和增量工具已交付；保留其规模/正确性回归，不重新列为新功能。
新的队列/会话目录在 10/100/1000 条规模记录开销，避免把审计全历史塞进每次检查点。

## 4．验收关卡与能力矩阵

每项采用四档事实：**已规划 → 实现/确定性通过 → 对应原生场景通过 → 可选分发通过**。
发布状态另记“已合并 / 已安装 / 已发布”。失败与未测保留，不用实现一半就关闭总问题。

| 关卡 | 放行需要什么 | 尚不能据此宣称什么 |
|---|---|---|
| 文件与责任 | 正文和初始责任共同提交、幂等/并发/崩溃恢复、延期/转交/收口负例 | 模型被唤醒、已理解、真实终端可靠 |
| 原生控制与通知 | 精确输入权、审批/草稿保护、独立通知回执、未知执行调查、原任务通过 | 停止了全部任务、零中断、严格 exactly-once |
| 会话体验 | 直接从项目打开默认历史选择器、分组、精确恢复；归档后证据仍可读 | 仅凭改标题或 kumi 折叠就称原生历史已隔离 |
| 审批与时效 | 操作绑定、授权范围、版本化决策、人类超时/迟到竞态、动作确认和真实时序 | 小模型低延迟即 30 秒达标；handled 即问题已解决 |
| 协作与接班 | 固定快照验收、独立缺陷检出、责任不断档、只有一个有效输入方 | 新验证者天然正确，换会话天然省 token |
| 分发与退出 | 旧任务回归、可选功能缺配置/服务、最小安装、关闭后责任接管 | 仓库可用即安装已更新，CI 文件存在即远端成功 |

Codex、omp、Hermes、OpenCode OMO、OpenCode pure 每个配置分别填写：
版本/profile/UI、存储/恢复、拒绝/停止、通知/恢复、归档、用量覆盖、真实证据和限制。
不得以一个宿主替全部通过；允许按已验证的组合选择性发布，未测自动动作保持关闭。

第一原生项目固定一个作者、一个验证者、同时做独立集成工作的调度方。先证明机械
消息送达，再加入可复现缺陷、延期、重启、关键迟到消息和未知工具结果。M2 扩展固定
版本返工，CQ-03 扩展接班，M3 扩展第二模块，分次增加变量并轮换角色。

每个已选对照组合先至少 3 次用于发现不稳定因素，不将小样本当普遍可靠性证明。
后端评测先协议夹具，后准备约 500–1000 条问题发现集与独立保留集；校准不看保留标签，
不以固定样本数自动授权。真实模型测试有明确配置/预算/数据范围，不能偷偷上传私有日志。

B 的 30 秒审批响应目标按既有发现→实际动作口径复测；同时报告发现→确认、无动作项、
超时和样本数。自动/协作者/人类路径分开，人类窗口期限独立，不扣掉未证实的等待来
美化时效。提醒期限、模型超时、human timeout 和审批 SLA 不能共用一个数字。
M1 文中的 120 秒检查、延期 2 次等仍只是 sandbox 参数，不在此次整合中变成生产默认。

## 5．可替换组件与选型决策

- **通知 transport：** 先原生状态/queue/hook 或受控 herdr 输入；hcom 是候选 adapter。
  只传短通知，验证精确实例、单一输入权、隔离配置/启停、无额外批准权限与回执差异。
  需要长期改本体才能满足语义时不采用；不用 hcom 不影响文件消息。
- **判定后端：** 现有 rules/Jev/command 影子入口保留。先核查用户报告中的样本/统计/
  配置，再选一个具备复现条件的候选；不规定必须 Jev，也不同时部署所有模型。
  Jev、Laya、Von、Foq、DeepSeek 报告配置的历史资料见[选型报告](APPROVAL-MODEL-SELECTION.md)。
  国内网络/鉴权/支付可用性、中文质量和费用分别验证，报告阈值 0.05 不作为默认。
- **模型辅助通知：** 只在无模型通知基线后验证净收益；状态/日志优先，有必要才判定。
  选时标签和审批 allow/deny/escalate 分开；logprobs/streaming 是能力而非质量保证。
- **会话历史：** 优先只分离 session 存储，其次受支持的可逆归档；整 profile 隔离需
  核对认证、skills、插件、安全依赖和后台范围。不移动共享数据库、不扫全 HOME，
  不默认无历史模式。只在 kumi 分组是明确降级，不能替代原生历史体验。
- **计量扩展：** 优先原版宿主的可选 hook/只读来源，不借换服务商/关闭后台或本体补丁
  制造“覆盖完整”。缺来源必须可见；模型失败不静默换端点，认证和私有数据边界不放宽。

这些都是选型门槛，尚未确定新增默认后端，也未安装 hcom 或新模型。
详细恢复/回执/权限规格分别见 M1、UX-02、判定报告和以下 AP 规格。

## 三级审批的实施规格（AP-01–AP-06）

以下是阶段 6 的详细契约；AP-02 影子研究可提前，真实执行仍须过该阶段对应门槛。

### AP-01：统一请求与决策契约

所有可识别的原生权限请求进入共同入口；普通问题、登录、信任确认和未知界面先分类，
不能默认当作可自动批准的工具权限。现有 `watch.py` 继续只读，`reviews.py` 继续记录事实；
新增执行职责单独承载，不偷偷让观察器开始发键。

审批记录至少关联：run/job/round、原生会话及操作 ID（可得时）、watch/seq/issue、
精确终端资源、完整操作/参数/cwd、授权策略版本、证据指纹、观察时间、责任人与期限。
请求内容或权限范围改变即需新决策。模型/提示词版本、截断状态、结论、分布与耗时留痕，
不将不存在的模型推理文字编造成解释。

决策记录与动作记录分开：`allow / deny / escalate` 是决策，提交动作、动作不确定、
确认允许、确认拒绝、已失效是执行事实。人类未回应记 `timed_out`，不写成用户明确拒绝；
本次操作按超时策略拒绝。具体 schema 在实现前固定，当前字段仅表达职责。

### AP-02：规则与小模型

- 程序负责能准确计算的身份、权限范围、时限与规则匹配；复杂命令解析失败不套用
  字符串前缀/子串白名单。整条操作的作用域不能由某个安全子命令代替。
- 小模型接受最少而充分的可信授权背景、完整操作与标记为数据的请求理由；回答
  边界清楚的问题。符合限定策略的结果可以直接进入批准执行，其他进入协作者。
- 用 kumi 自有契约衔接规则基线与可选后端，具体次序见[选型报告](APPROVAL-MODEL-SELECTION.md)。
  Jev 固定版本、本地 Laya 多语言版、Von 英文子集和待核查的 DeepSeek 报告配置均为
  候选；先审报告原始证据，再选择一项具备复现条件的影子对照，Foq 先补证据与部署审查。
  记录权重/语言/实际输入、重试与资源成本；接口兼容不证明置信度同义。
  未配置或失败时正常升级复核，默认不同时调用所有候选，不把本地失败自动转成远端外发。
- 阈值按任务与宿主样本校准，不直接照搬 `0.95`；识别不完整、超长/截断、输出畸形、
  服务超时或不可用都不得转成自动允许。模型概率也不能覆盖明确拒绝规则或新增授权。
- 先影子运行：只记录建议与既有结果对照；再启用通过验收的授权类别。Jev 远端评估
  使用合成/脱敏数据；真实项目证据是否外发必须是明确的运行配置，不因接入 API 自动外发。

### AP-03：审批协作者

为审批设明确职责与有限上下文，可复用专门实例，不必每次启动新 agent。
派给它的是当前操作、任务/授权摘要、小模型结论、缺失信息和相关历史，不是全部项目转录。
它可在已有委托范围内批准或拒绝；缺用户授权/偏好才上报人类。它不能把自己对风险的
判断当成用户新增授权，也不能通过发消息给作者转移原生权限。

审批服务接收结构化复核结果，由唯一输入执行方执行；协作者不和调度方争抢终端。
协作者不可用、过期或自身遇到权限阻塞时升级，不递归创建无限审批 agent。
定义协作者响应预算、总待办年龄、公平队列和并发上限；不让一个请求拖住其他子 agent。

### AP-04：人类限时窗口

窗口显示任务/agent、完整操作及可展开详情、目标位置、上报原因、有效期限，提供
“允许本次 / 拒绝本次”。默认不授予永久权限，不强行切换到子终端；允许显式查看证据。
计时从确认窗口已展示开始，同时设置独立的展示失败/总请求期限，避免无人可见的无限等待。
秒数先做 run 配置，使用短时模拟测试竞态；实际默认值在体验试验后确定。

到期未获允许按用户提出的策略拒绝本次操作。关闭窗口按拒绝本次处理，并记录关闭来源；
窗口显示失败单独记录，不冒充人类看过。到期、点击、任务取消通过同一版本检查提交，
只能产生一个生效决定；迟到点击、重复通知和恢复后的旧窗口不能批准新操作。
重启后保留原截止时间，不因重启重新给一整段倒计时；没有 GUI 时使用可用的审批界面，
若无法呈现则走展示失败的有界处置，不能自动允许。

### AP-05：宿主执行与持久服务

定义宿主级 `approve_current` / `deny_current` 能力；优先使用带操作 ID 的公开接口，
其次采用已实测的精确 UI 选项。**不把所有超时拒绝实现成 Esc**：Esc 在不同界面可能
关闭选择器、打断整轮或没有完成中断。发键前重读目标，操作后验证请求已按预期解决。

服务是显式启动、可停止、有健康状态的 run 级后台组件，使用持久队列；后续可选托管，
不默认改系统启动项。模型暂时不参与巡视也能处理已授权类别；服务死亡时保留待办并
显示监督缺口，不能宣称仍在监控。队列执行按目标串行，跨目标可并行；租约、重启、
丢回执、取消和控制器接班都要恢复。

同一时刻每个目标只有一个输入执行方。现有本地租约不能阻止绕过 helper 的任意终端
输入；纯 TUI 的读屏和发键之间也不是原子操作。没有足够身份或窗口稳定性时保留
未解决状态并升级，不宣称严格 exactly-once 或绝对可靠的自动点击。

### AP-06：拒绝、反馈与重提

确认拒绝后，告诉作者：拒绝来源（策略/协作者/人类/超时）、必要依据或缺失信息、
允许的替代范围。作者可以补充新事实、缩小操作范围或选择无需该权限的办法。
主动拒绝不能被简单改写理由绕过；超时不意味着操作已被判有害，但也不是允许。

同一操作绑定原请求和前次决策；语义未变、没有新依据的重提不反复弹窗。
配置单问题重提次数、冷却与总预算；耗尽后保持 blocked 并给负责人明确结论。
替代方案仍须符合相同授权边界，不通过换工具规避原拒绝。
拒绝后先确认宿主输入就绪再反馈；若已有有效 result，依现有协议用新轮次推进，
不改旧结果。拒绝一个操作与取消整个 job 分别记账。

## 6．验收分工、网状协作与接班

### 验收分工与返工

CQ-02/04/05、DH-05 从任务开始就固定风险、spec/oracle、覆盖缺口和独立检查负责人。
低风险采用针对性机械检查；并发、状态机、跨层接线、外部输入优先安排独立探针。
不机械每轮全量重建，也不因追求低 token 省略变化涉及的检查。

验证者针对固定快照报告根因、证据、严重性和未覆盖项；调度方审证据完整性、冲突、
必要抽查和集成。验证者修改被验收代码后，相应部分另有独立复验。保留验证装置
负对照与原始失败；重试有理由/上限，测试全绿不等于规格完整。
报告类交付先做明确配方，是否新增 report schema 按实现需要决定，不先豁免产物验证。

M2 先允许作者与验证者直接澄清，再在明确委托中推进拒收/修复/复验。验收权、终端
输入权、切轮/关闭权分别记录。原生会话已有 result 时，继续修代码要进新轮，不改旧结果。

### 网状协作

M0 发现同伴，M1 有界问答，M2 验证协作，M3 才加入跨模块接口/依赖/资源冲突。
普通消息无需调度方逐条批准；改变任务范围、共同接口决定、写入所有者或验收标准时，
由相应负责人记录有效版本。超期依赖、相互等待与取消传播必须有升级出口。
M4 只评估有预算的局部协调，限制 fan-out、往返次数、总时长和创建成本；不全员广播。

每个 agent 启动只得到职责相关的成员摘要、工具入口与短协议；正文、证据按需读取，
不把本计划和全部历史塞入所有提示。任何退出/替换/接班都保留未读和未处理责任。
执行能力不足时保留明确显式转述退路，但已启用消息不可直接停服务并丢掉待办。

### 显式接班

CQ-03 安排在复杂 M3/M4 前，不用无限嵌套表达同一职责替换：
后继只读准备 → 核对交接包 → 旧方停止派单/输入 → 转移控制与监督 → 后继确认接续。
后继准备时旧方仍负监督责任，接管失败不能双重输入，也不能无人负责。

交接包包含任务/授权、精确源码与未提交工作、决策理由、验收/未覆盖项、原生会话、
活跃子任务、消息/审批、uncertain 动作、用量预算、下一步和失败恢复入口。
不同账本通过精确引用和确认衔接，不声称跨文件自动成为原子事务；注入各交接边界崩溃。
同一职责可由不同宿主接替，但配置/写入范围和身份必须重验。

先演练作者与调度方显式接班，再依据真实上下文、缓存、压缩、进展和预算选择触发策略，
不设通用固定 token 阈值，不默认复制整个会话或删除旧历史。接班不会自动完成独立验收。

## 7．计量、质量与节省 token 的验收

优化按可归因变量实施：缩短常用摘要/增量读取 → 工具负责机械等待和提醒 → 同伴直接
交流 → 有界委托验收 → 显式接班 → 可选判定模型。这个列表是待比较的因素，
不是要求每个因素都先于下一个完成的第二条开发队列。

每次原生运行从启动登记 controller、worker、verifier、原生子任务及后台来源；
阶段检查点采集，失败也留记录。缓存输入子集、非缓存输入、输出、请求/重试次数与
未知覆盖分别报告，不直接按累计 token 乘统一单价。费用标 provider/模型/价格版本，
没有可核查口径时保留 token 与未知费用，不虚构总成本。

对照使用相同任务、基线、输入、验收、宿主/模型配置和预算，一次改变一项机制：
显式转述 vs 直接文件消息；状态通知 vs 模型辅助；集中审核 vs 委托；继续/压缩 vs 接班。
主动延期与投递失败分开计时，原生后台/模型判断/提醒唤醒/恢复/返工都计成本。
跨来源别名、复制/分叉记录与跨 job 迁移的冲突先解释；不能换 ID 绕过去重。

质量指标包括旧缺陷族检出、错误拒收、验证装置误判、集成通过、错投/误批准、
重复副作用、未读遗失、无人接管、监督空窗。工程质量相当且覆盖可解释才能比较节省；
无充分证据不公布“网状省 X%”。部分来源未知可做有界子集研究，不能宣称完整项目胜出。

## 8．开发位置、交付与发布

- main 保留稳定运行工具和主线修复；`experiment/peer-notices` 开发 M1，先同步所需
  main 基线。UX-02 只读/通用记录可独立实现；消息耦合部分随实验验证。不要从 runtime
  import tests/experiments，也不要为方便直接把 E2E runner 整体分发。
- AP 影子后端/样本继续在开发目录；真正运行能力验收后只提炼必要 helper、短协议和
  参考进六个同级 skills。新 optional adapter 不把模型框架变成所有用户必装依赖。
- 每小批交付代码/针对性测试/可重跑 demo/限制/状态更新及一个具体下一单元。
  涉公共控制与 schema 的改动跑完整相关回归/分发；纯文档做差异、链接及内容核对。
  真实模型和终端证据与合成测试分开，升级后旧证据不自动续期。
- 阶段 5 通过的基础消息和会话能力可先以显式可选功能交给用户复测，不必等所有
  AP/M3/M4 完成。开发先跑基础/故障实验，再请用户评价实际项目体验。
- UX-02d 的旧历史操作先给绑定清单/预览；保留一个非 kumi 用户会话做干扰对照。
  不自动迁移旧 run、删除 native 历史或清空私有存储；运行目录仍被引用时继续保留。
- 正式发布核对最小复制包/离线运行、当前宿主真实 skill 发现、默认关闭与退出流程、
  可选插件隔离/卸载、文档、MIT/第三方许可、隐私/凭据和实际远端 CI。
  新功能关闭前显式处置/交接已有责任，不能回退后静默丢消息或审批。
- 本地提交、实验通过、合并 main、同步个人安装、远端推送/发布分别记录；后两者按
  实际授权处理，本次统一规划不执行它们。
