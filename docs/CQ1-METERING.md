# CQ-01：最小计量闭环

日期：2026-09-23。实现前基线：`ac5e0fe`。

## 本批交付

新增 `usage.py register-metering` 和 `usage.py checkpoint`，把既有原生导入器与
来源审计串成可重复执行的入口，未新增模型调用或后台服务。

- run 内保存不可变计量计划，明确 controller、轮次和已发现原生子来源的绑定、
  账本位置、角色、阶段与重试归属。空计划也可登记，缺口保持可见。
- 阶段检查点先核对来源与归属，再导入指定原生调用，最后重做审计；终端返回小摘要，
  完整报告保存在 run 内。检查点标签不重写调用的阶段归属。
- 复用已有样本身份与原子逐调用写入，重复采集不重复计数。待完成来源的导入失败
  不阻止其他有效来源；入口证据或归属错误则先阻止采集。失败批次可能部分落盘，
  明确标记导入计数不完整，并从最终审计读取实际账本状态。
- 已记录用量与完整总量分别展示。新增逐调用计算的非缓存输入，缺任一计数时保留
  unknown，不能用两组不完整的总和相减得到“非缓存用量”。
- 使用说明见[计量计划与检查点](../skills/agent-orchestrator/references/metering.md)。
  原有 `import-native`、`audit-sources` 与单独汇总命令继续可用。

## 验证

新增 19 项无模型回归，覆盖 controller/author/native verifier、重试、CLI 重启重导、
增量追加、空计划、新轮/新子来源、pending、缺日志、证据变化、错误归属、计划篡改、
路径重定向、部分落盘后续采、最终审计失败，以及四宿主的原有计量边界。

独立 sandbox 演练通过实际 CLI 连续执行四个检查点：

| 检查点 | 预期与结果 |
|---|---|
| startup | 空计划显示 controller 与已准备轮次缺口；完整总量为 null |
| missing-native-child | 已导入父会话和 controller，发现漏绑原生 verifier；完整总量仍为 null |
| verification | 明确补绑 verifier 和重试归属后，3 个合成调用纳入账本 |
| after-restart | 新 CLI 进程重导 3 个调用均判重复，新增为 0，总量不变 |

演练使用合成 OpenCode SQLite 形状，没有启动模型或修改 DataHive。合成输入为 300、
缓存子集 180、非缓存 120、输出 60，仅用于验证算术与归属，**不代表真实项目成本**。
私有绝对路径和原始报告不收入公开包。

全量回归 511 项：498 项通过，13 项需显式启用的 tmux 测试跳过；本批未改变终端传输。
分发包 148 个本地链接及差异检查通过。当前环境没有 mypy/black 模块；使用可用 Ruff
检查本批代码，新增文件经 Ruff 格式化；不声称通过 mypy 严格类型检查。
