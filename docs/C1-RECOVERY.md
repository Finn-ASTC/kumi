# C1：分页恢复摘要

2026-09-20 完成 opt-in `runs.py recover --summary`。日常巡视可以减少重复读入模型上下文的任务、历史轮次和 watch 目标列表；完整恢复接口保持兼容。

## 使用与边界

```bash
python3 skills/agent-orchestrator/scripts/runs.py recover \
  --run "$RUN_FILE" --summary --limit 10
```

任务、watch、错误、待处理事件和等待用户回复分别分页。摘要保留整次恢复的计数、部分失败标记、所有页面的观察异常统计，以及待办的精确身份、处理版本、原备注和证据路径。具体分页与下钻命令在[运行包恢复说明](../skills/agent-orchestrator/references/runs.md)。

- `complete` 只表示持久记录是否完整读出，不表示任务完成或监督健康。后续页的错误也会令它保持 false。
- 健康计数包含保留的历史 watch，同一目标可能被重复统计；缺记录保持未知。摘要不检查实际观察器寿命、监督归属与当前覆盖，继续独立工作仍使用 `supervision.py`。
- 时间诊断每次重新计算，即使文件没有更新，也能反映成功观察变旧及 monitor 过期。
- 限制的是每个列表的行数；长备注、错误文本仍保留，因此不是严格字节/token 上限。分页期间记录可能改变，每次巡视及记录改变后重置所有 offset。
- 本次仍全量读取状态，没有缓存、持久游标或 delta；C2 尚未实现。
