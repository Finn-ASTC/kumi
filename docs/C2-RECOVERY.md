# C2：源内容增量读取与变化交付

2026-09-20 完成 `runs.py recover --delta`。它复用元数据未变的源文件内容，保留跨进程续读记录，按页返回 compact job/watch 的最新变化。默认完整恢复和 C1 摘要仍保持只读；新模式仅在 run 的 `recovery/<id>/` 内写入私有缓存、续读记录及锁文件。

## 使用

```bash
# 首次读取，返回 cursor_path 和 next_cursor
python3 skills/agent-orchestrator/scripts/runs.py recover \
  --run "$RUN_FILE" --delta --limit 10

# 收到并应用上一条回复后，以它提供的路径和 token 续读
python3 skills/agent-orchestrator/scripts/runs.py recover \
  --run "$RUN_FILE" --delta --limit 10 \
  --cursor "$CURSOR_FILE" --since "$LAST_RECEIVED_TOKEN"
```

每次先处理 `reset`，再按 ID 应用 upsert/remove；后续页仍有变化时继续使用刚收到的新 token。尚未返回的变化会保留，频繁变化的早期任务不会抢占已有积压的顺序。权限待办、waiting_user、错误、总数和健康统计每次返回，不作为变化事件省略。完整操作约定在[分发包参考](../skills/agent-orchestrator/references/recovery-delta.md)。

丢失输出后的旧 token、缺失或损坏的游标、版本或筛选条件变化会重新建立基线。部分恢复仍显示有效待办和 upsert，但暂缓 remove，避免把读不到的数据解释成删除。缓存文件和续读记录分开原子发布；两者之间中断时，下一次校验失败并重建。磁盘源内容未变时，缓存文件不重写。

## 可复现规模检查

新增开发工具 [recovery_benchmark.py](../tests/recovery_benchmark.py)，不安装到 agent skill 目录。它创建并保留独立夹具，不启动终端或模型，不改宿主配置：

```bash
python3 tests/recovery_benchmark.py --root "$EXISTING_SANDBOX_PARENT"
```

可用 `--skills-root "$COPIED_SKILLS"` 验证仅复制六个 skills 的独立分发包。本次在 Linux、Python 3.14.7 上使用该模式验证。每个任务只有一个已登记、未提交的轮次；一个未执行观察的 watch 覆盖全部任务，因此其健康保持未知。输出按 UTF-8 CLI JSON（含换行）计字节；所有展示 `limit=1`，诊断时间 `now=101`。delta 续读测量前已接收全部基线页；“单任务变化”通过一次合法 job claim 产生新修订。

首次 delta 也会复用同一次恢复中重复读取的源内容。续读保留一次 run 预检源读取；其余内容来自缓存。这里计的是应用执行的内容读取，不是 OS 磁盘缺页，也不包含打开文件、检查元数据和扫描目录的次数。

**缓存开销仍然存在。** 100 任务无变化续读还读取 595,270 字节的内容缓存及 10,777 字节的续读记录，写入 10,777 字节的续读记录，另读取 611 字节的 run 源文件；内容缓存写入为零。源内容变化时可能重写整个有界缓存。单次墙钟时间有波动，小规模及部分较大规模样本没有变快，因此没有普遍加速结论。

路径长度、文件元数据、待办、页大小及历史规模都会改变上述数字。首次 delta 带有续读信息，可能比单次摘要更大；只查询一次时仍优先使用 summary。此处没有测量 token、费用或单／多 agent 净收益。

## 验证与边界

- 新增 [18 项回归](../tests/test_recovery_delta.py)：跨进程续读、分页积压、公平顺序、丢失输出、损坏/版本/筛选失效、时钟过期、观察锁变化、旧问题与新权限、缺健康记录、页外错误、请求替换与 mtime 恢复、非普通文件、缓存上限、游标锁、写入失败和两文件发布中断。
- 全量 **470 项通过，含 13 项自有临时 socket 的真实 tmux 测试，零跳过/失败**；没有原生模型调用。
- 独立分发包检查为 6 个 skills、30 份 Markdown、139 个本地链接、零发现。修改前后的参考应用检查分别确认了缺失能力，以及仅依赖运行包即可找到开始、续读、重建、分页与监督方法。
- 缓存最多保留 4 MiB 源内容／4,096 文件；超出后正常读取。每个序列化缓存或续读文件上限 32 MiB。内容仍可能包含任务与结果，只留在私有 run 中，不作为部署文件提交。
- 每次仍扫描目录、打开并检查文件元数据、解析和验证 JSON，时间决策及锁状态重新计算。依赖本地文件系统的元数据一致性；缓存校验和用于检测损坏，不提供恶意写者隔离。
- 变化列表描述 compact 行，不能替代轮次/交付详情和完整事件审计。`complete=true` 也不能证明监督覆盖；独立工作仍使用未启用缓存的 `supervision.py`。
