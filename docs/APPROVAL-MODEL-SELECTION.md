调研日期：2026-09-23；项目基线：`8eb5c67`。这是 AP-01/02 的选型细化，
尚未安装模型、调用收费 API、上传项目证据或执行自动审批。以下上游数据是作者／
评测者报告，不是 kumi 实测。实际接入时重新核对并固定源码、权重、SDK 和配置版本。

2026-09-24 进展：已交付[通用后端 v1 与影子试验工具](APPROVAL-SHADOW.md)，内置规则与

## 当前选择

2026-09-24 补充：用户提供的本地判定报告提出 DeepSeek flash＋logprobs 的实测线索。
已完成正文审阅，原始结果/标签/精确配置尚未核查；加入候选但不采用其 0.05 阈值为

不要求先试 Jev。具体问题与完成条件见[报告跟进计划](DECISION-LAYER-FOLLOWUP.md)。

**既有候选安排：Jev 可选云端、本地多语言 Laya、Von 英文子集、Foq 观察项；新增
DeepSeek 报告配置待核查。** 实际评测次序按复现条件和预算选择，不是模型排名。

- 可选 Jev adapter 已在开发工具中实现；云端数据处理已获允许且有可用凭据时，固定
  `jev-1.13.0` 开展不执行动作的影子判断。远端服务不是公开运行包的必需依赖。
- 必须本地处理时，先做规则＋协作者的可用链路；Laya multilingual 作为可微调、
  可校准的候选。未通过测试前，不为凑齐“本地自动审批”而放宽门槛。
- Von 1.1 适合验证短英文语义判断的潜力。中文、混合语言授权不默认经自动翻译
  交给它：翻译本身需计成本与核对否定、范围、路径和用户原意。
- Foq 进入第二轮前，先补证据完整性、校准和实际运行依赖检查。
- 目标闭环中，模型未配置／失败时交规则与指定审批协作者；需要新增用户授权时再
  进入人类窗口，超时拒绝本次操作。当前影子工具只记录 escalate，尚不创建这些待办。

判断依据与 kumi 自身设计建议在下面分开。不能依据通用分类分数或宣传延迟，
直接给任何候选设置全局自动放行阈值。

## 候选比较

## 为什么优先评测 Jev，但不直接上线放行

官方提供明确的版本、限额和结构化接口。当前请求总预算为 64k token，state 加最长
单问题不超过 32k；这也不意味着审批应该输入完整 agent 历史。只传本次操作所必需的
任务授权、操作、作用域和证据，超过容量时升级复核，不能静默截断。[S1]

两个有公开输入／结果的社区评测为优先试 Jev 提供了线索：

- `jabr/classifier-benchmark` v2 的 49 项任务、866 个合成案例报告 macro accuracy：
  Jev 0.966、Von 1.1 0.720、GLiNER2 0.684、Laya 0.583。该集合由模型生成和交叉
  检查，且公开可被用于训练；不是中文 shell 授权测试。[S8]
- `sysone-bench` 使用相同问题的多套测试，显示 Jev 在部分 guardrail／多语言样本占优，
  Laya 在部分分类任务更好。多语言子集仅 25 个状态；Laya Router 相比英文 checkpoint
  的结果不同，不能拿“Laya”这个名字混合所有版本。它也显示高置信过滤后仍有错误。[S16]

因此本计划选择的是**更值得先做工程验证的基线**，不是“所有场景 Jev 最强”。
官方自己列出数字、间接推理、无关长上下文和对抗内容等失败模式。[S2]
身份、租约、到期、路径／资源约束和政策硬规则仍由程序检查。

按官方当前单价举一个假设：10,000 次判断、每次总计费输入 2,000 token，输入费约
`10000 × 2000 / 1000000 × 0.042 = $0.84`。这不包含重试、协作者推理、网络、运维，
也不是 kumi 成本实测。有限审批量下，选择本地模型的理由应包括隐私、离线和可定制，
不能仅用“无 API 账单”推导成本一定更低。[S1]

## 本地路线的具体限制

### Laya：面向业务的小模型候选

作者文档承认基础 checkpoint 在 typed-decisions 零样本测试中接近随机，较好的专项
成绩来自该任务训练集上的微调；还披露 `noul` 标签偏差、`score` 顺序偏差和
`action.act_probability` 缺少有效信号。因此第一版优先比较显式三选一 `choice`，
不把 act/escalate head 或概率字段直接当作执行许可。[S4]

多语言 checkpoint 默认预算 1024 token，问题／选项会占用其中一部分，且出厂未完成
业务校准。英文模型不能直接覆盖中文；本轮读取的 0.3.7 Router 已与早期评测所用
路由行为有所不同，测试要固定 checkpoint 与路由配置。加大编码器支持的长度不证明
长输入判断质量稳定。[S5–S6]

第一版采用独立进程／可选本地服务，避免给 kumi 标准库工具强制引入 PyTorch。
先用不做微调的结果建立基线，再以真实失败类型决定是否训练。训练、校准、最终测试
按项目与命令族分开，不能把同一模板改几个路径就当成独立测试集。

### Von：英文候选，不能拿上下文容量当推理能力

模型卡明确披露长、多条款、多步组合判断的弱点，且公开校准数字部分属于用于拟合的
公共数据。评测需要同时固定 encoder、Option-Marker head 和 calibration 文件，
不能仅记录一个仓库名。适合先测短英文命令说明和风险标签；若引入翻译，按独立
管线计成本并验收，而不是隐藏在公平对照里。[S7]

### Foq：先补集成证据，再进入审批候选

Foq 对 Laya 的显著优势表来自 **9 个**对照案例；另有作者的 150 例 operational exam
和 500 例阈值测试。不能由此认定它对中文授权、任意 shell 和提示注入都有同样表现。
仓库对 Jev 上下文的对比也与 Jev 当前官方文档不一致，规格以各自一手资料为准。[S9–S10]

静态源码审阅还发现：标量路径调用 `/completion` 请求一个输出 token，多问题通过
多个请求并发；缺候选 logprob 会先填固定值，再归一化并返回 `success=True`。
这是未来 adapter 必须检查概率来源完整性的理由，不是本轮已复现某种真实误审批。
不能把未出现的候选概率当成足够证据，也不能把“只输出一个 token”计成零输入成本。[S11]

参考权重依赖支持 PQ2_0 的专用服务端，普通 llama.cpp 不能直接加载；安装 Python 包
不等于完成本地部署。[S9] 如进入第二轮，保留原始概率、缺项、实际模型身份和校准
配置，重新验证超长输入与中文。其默认温度／0.95 阈值不跨业务移植。

## kumi 接口与执行职责

建议 AP-01/02 使用 kumi 自有决策契约，各后端 adapter 转换输入输出。兼容同一 HTTP
路径不意味着置信度、截断、错误、重试与计费行为相同。尤其 Jev 的 Choice/Score
`confidence` 是分布的汇总指标，Noul 不提供该字段；其他后端可能使用最大类别概率。
“全部模型统一 confidence > 0.95”没有成立依据。[S3、S11]
chat/logprobs/流式可作为某类适配器能力，不要求所有后端支持；缺概率保留缺失，
不静默换服务。能力探针也要明确外发范围和调用预算。通知时机与审批分别设计标签、
校准和任务契约，通用 transport 不代表共用业务阈值。

建议每次观察至少记录：

- request/operation/evidence 指纹、政策版本、有效期限、输入完整性与实际语言；
- 后端、实际模型／权重 revision、adapter／问题／校准版本和截断状态；
- 原始标签分布、其含义、候选 `allow / deny / escalate`，以及结构化风险／缺失信息；
- 耗时、重试、可得 token、数据处理位置、观测错误；不编造模型没有返回的推理文字。

模型只给建议，政策执行层核对已有授权后才产生决定；程序确定的限制不可由概率覆盖。
同一有效决定最终交给唯一宿主执行方，沿用 DH-02/03 的意图、动作不确定与确认回执。
失效、缺输入、异常、输出不合法、调用超时均不得当作允许。人类窗口计时与拒绝反馈
沿用 AP-04/06，不因换模型改变语义。

默认运行只用**一个**已经配置并通过验收的后端，多个模型同时评分只用于有预算的
影子对照。这样避免每次申请变成多模型投票与多次调度对话。跨后端 fallback 必须
事先配置：本地失败不能偷偷把私人操作上传云端，云端失败也不能换到未校准本地模型
继续自动放行。Jev 的“不用于训练”说明也不等于默认零保留承诺。[S1]

## 首轮评测与晋级条件

1. **先落 AP-01 契约和规则基线**，保留不接模型也能走协作者／人类的完整路径。
   决策后端不能先于精确原生操作关联和回执就开始发键。
2. **建立独立离线样本**：首批约 500–1000 条只用于发现问题，包含中文／英文／混合、
   已授权但有风险、无危险但未获授权、修改授权范围、明确拒绝后的重提、同命令不同
   cwd、路径／符号链接／重定向／复合 shell、网络与凭据、长文本末尾关键限制、
   缺页／截断、伪造用户授权、超时／旧 operation ID。无法仅凭输入确定时标为升级。
3. **固定输入做影子对照**：规则、Jev、Laya multilingual/Router、Von 英文子集，另留
   一个固定配置的现有协作者 LLM 基线。每个候选报告全部适用范围和不支持／拒收的
   请求数，不能剔除难例后只比准确率。各后端专项提示调优需单列于相同问题基线。
4. **按错误放行约束选覆盖率**：同时报告“应拒绝／升级中有多少被允许”和“所有自动
   允许中有多少是错的”；另报误拒绝、协作者／人类升级比例、分语言／长度／命令族
   的校准和风险覆盖曲线。零观察错误不是零风险证明；少量样本不直接批准全量上线。
5. **测端到端代价**：请求发现→判断→执行→确认的 p50/p95、服务冷启动、并发排队、
   失败退路、CPU/RAM/VRAM、真实计费输入、重试和升级后的协作者 token。与仅用
   协作者复核比较，不能用模型单次延迟或无生成 token 代替整条链路成本。
6. **有界类别上线**：只有独立保留集、现场影子运行和对应宿主动作矩阵均通过的
   授权类别才能启用自动处理。校准阈值属于版本化配置；模型／政策／提示改变后重验。
   协作者无法决定或缺少用户授权的分支继续进入限时人类窗口。

阶段性验收按 AP-01/02/04/05 跟踪，不新增一套彼此重复的任务编号。Jev 的额度／账号
或网络不具备时照常推进契约、规则与离线夹具，不借此暂停整个 B 主线。
